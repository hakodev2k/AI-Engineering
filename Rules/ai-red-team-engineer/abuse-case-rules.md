# Abuse Case Analysis

## Purpose
Identify harmful system uses that may not require a conventional vulnerability.

## Scope
User workflows, agent capabilities, content generation, automation, integrations, and scale effects.

## MUST
- Model realistic malicious users, compromised users, insiders, and misuse of intended capabilities when relevant.
- Tie abuse cases to actual system affordances, prerequisites, scale, and mitigations.
- Evaluate whether safeguards fail under repeated, adaptive, or compositional use.

## MUST NOT
- Dismiss abuse because individual actions are permitted when composition creates material harm.
- Report speculative scenarios as demonstrated findings.

## SHOULD
Prioritize abuse cases by plausible impact, accessibility, scalability, and mitigation gaps.

## Exceptions
Out-of-scope abuse classes require documented rationale and residual-risk ownership.

## Verification
Review system capabilities, user journeys, test evidence, prerequisites, mitigation behavior, and stated uncertainty.
