# Definition of Done Rules

## Purpose
Protect transparent quality and a shared meaning of Done.

## MUST
- Ensure the Scrum Team has access to an explicit applicable Definition of Done.
- Make quality gaps visible when work fails the Definition.
- Facilitate strengthening the Definition when recurring defects or risks reveal insufficiency.

## MUST NOT
- Count incomplete work as Done to improve Sprint metrics.
- Quietly waive mandatory quality, security, compliance, or release criteria.

## SHOULD
Promote automation and objective verification of Done criteria where practical.

## Exceptions
Any authorized exception to external mandatory criteria requires documented risk, owner, approval, and remediation plan.

## Verification
Compare completed increments, quality evidence, defects, and applicable Done criteria.
