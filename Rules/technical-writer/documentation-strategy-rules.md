# Documentation Strategy Rules
## Purpose
Ensure documentation investment follows user risk, product goals, and lifecycle needs.
## Scope
Documentation portfolios, roadmaps, ownership, and governance.
## MUST
- Define target audiences, critical journeys, content owners, lifecycle state, and success evidence for major documentation areas.
- Prioritize documentation using user impact, operational risk, support burden, change frequency, and business obligations.
- Define authoritative sources when multiple documents describe the same behavior.
## MUST NOT
- Treat documentation as an unowned release afterthought.
- Create parallel authoritative sources without an explicit synchronization strategy.
## SHOULD
- Maintain a documented information architecture and retirement policy.
## Exceptions
Emergency documentation may bypass normal planning only when owner, expiry or follow-up, and known gaps are recorded.
## Verification
Review the documentation roadmap, ownership map, analytics/support evidence, lifecycle labels, and source-of-truth declarations.
