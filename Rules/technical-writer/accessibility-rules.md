# Accessibility Rules
## Purpose
Make documentation usable by people with diverse abilities and assistive technologies.
## Scope
Text, structure, images, media, tables, interactions, and downloadable content.
## MUST
- Use semantic heading hierarchy, meaningful link text, text alternatives for informative visuals, and accessible table structure.
- Provide equivalent information for content conveyed only through color, audio, animation, or imagery.
- Ensure interactive documentation features are keyboard operable and expose accessible names where applicable.
- Include accessibility in review for new content patterns and tooling.
## MUST NOT
- Use screenshots as the only source of required textual instructions.
- Publish essential video/audio content without appropriate accessible alternatives.
## SHOULD
- Follow applicable WCAG guidance and test high-value journeys with accessibility tooling and representative assistive technology.
## Exceptions
Temporary inaccessible third-party artifacts require documented limitation and the best available equivalent alternative.
## Verification
Automated accessibility checks plus manual keyboard, structure, alt-text, contrast, and screen-reader spot checks.
