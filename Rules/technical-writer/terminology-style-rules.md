# Terminology and Style Rules
## Purpose
Maintain precise, consistent language without sacrificing technical correctness.
## Scope
Voice, terminology, naming, abbreviations, grammar conventions, and inclusive language.
## MUST
- Use canonical product, API, domain, and UI terms consistently with their authoritative sources.
- Define uncommon abbreviations and overloaded terms before relying on them.
- Prefer direct, unambiguous instructions and distinguish requirements from recommendations.
- Preserve exact casing and spelling for code-sensitive identifiers.
## MUST NOT
- Rename technical concepts merely for stylistic variety when doing so creates ambiguity.
- Use stigmatizing, exclusionary, or needlessly personifying language where neutral precise language exists.
## SHOULD
- Maintain a shared style guide and terminology list enforced by linting where practical.
## Exceptions
Quoted interface text or externally governed terminology may retain nonstandard style when exactness is required.
## Verification
Editorial review, terminology linting, UI/source comparison, and search for conflicting synonyms.
