# Information Architecture Rules
## Purpose
Keep documentation discoverable, predictable, and scalable.
## Scope
Navigation, hierarchy, content types, taxonomy, and cross-linking.
## MUST
- Organize content around user tasks and stable concepts rather than internal team structure.
- Give each topic a clear purpose and canonical location.
- Preserve stable navigation paths or redirects when restructuring published content.
- Define taxonomy terms consistently across navigation, metadata, and search facets.
## MUST NOT
- Duplicate complete topics merely to make them visible in multiple navigation branches.
- Bury critical prerequisites or safety information in unrelated sections.
## SHOULD
- Use progressive disclosure so overview, task, explanation, and reference content remain distinguishable.
## Exceptions
Deliberate duplication for offline or regulated packages requires an ownership and synchronization mechanism.
## Verification
Run link checks, navigation review, search tests, tree testing where appropriate, and duplicate-content review.
