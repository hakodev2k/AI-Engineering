# Change Control Rules

## Purpose
Keep material program changes explicit and traceable.

## Scope
Scope, schedule, budget, architecture, launch, dependency, and ownership changes.

## MUST
- Material changes MUST record reason, impact, owner, decision authority, and affected commitments.
- Approved changes MUST update the authoritative plan.
- Changes affecting shared commitments MUST be communicated to impacted stakeholders.
- Urgent changes MUST receive follow-up documentation and review.

## MUST NOT
- MUST NOT maintain conflicting unofficial plans after approval.
- MUST NOT bypass decision authority for material commitments.

## SHOULD
- Change handling SHOULD be proportional to impact and reversibility.
- Repeated changes SHOULD trigger review of planning assumptions.

## Exceptions
Exceptions require rationale, owner, impact, and follow-up date.

## Verification
Review change records, approvals, plan revisions, and stakeholder communications.
