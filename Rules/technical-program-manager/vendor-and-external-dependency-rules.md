# Vendor and External Dependency Rules

## Purpose
Control delivery risk introduced by vendors, partners, and external service providers.

## Scope
Third-party software, services, contracts, integrations, and delivery dependencies.

## MUST
- Critical external dependencies MUST have documented owner, commitment, contingency, and acceptance criteria.
- Vendor timelines used in program commitments MUST be based on confirmed evidence.
- Integration obligations and support boundaries MUST be explicit.
- Material vendor changes MUST update program risk and schedule records.

## MUST NOT
- MUST NOT treat vendor assurances as equivalent to validated readiness.
- MUST NOT leave critical contractual or technical assumptions unowned.

## SHOULD
- Programs SHOULD identify substitute or fallback options for high-impact external dependencies.
- Vendor performance SHOULD be tracked against objective commitments.

## Exceptions
Exceptions require rationale, exposure, mitigation, owner, and review date.

## Verification
Review vendor commitments, interface records, acceptance evidence, contingency plans, and status history.
