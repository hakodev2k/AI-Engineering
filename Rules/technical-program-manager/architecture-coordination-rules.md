# Architecture Coordination Rules

## Purpose
Coordinate technical decisions across teams without overriding technical ownership.

## Scope
Cross-system design, interfaces, platform dependencies, migrations, and technical reviews.

## MUST
- Cross-team technical decisions MUST have a named technical owner.
- Interfaces MUST document ownership, contract expectations, and change handling.
- Program plans MUST include required technical reviews before major implementation commitments.
- Important technical assumptions MUST be tracked and validated.

## MUST NOT
- MUST NOT override accountable technical owners merely to preserve a date.
- MUST NOT hide unresolved technical disagreements in status reporting.

## SHOULD
- High-uncertainty technical work SHOULD be sequenced early.
- Important decisions SHOULD document trade-offs and operating impact.

## Exceptions
Exceptions require technical-owner approval, rationale, risk, and follow-up.

## Verification
Review decision records, interface documents, review evidence, assumptions, and plan links.
