# Security and Compliance Rules

## Purpose
Ensure security, privacy, compliance, and control requirements are integrated into program execution.

## Scope
Programs affecting sensitive data, regulated systems, identity, access, infrastructure, or security controls.

## MUST
- Applicable security and compliance requirements MUST be identified before dependent implementation decisions.
- Required security reviews MUST be scheduled early enough to influence design.
- Open security findings affecting release decisions MUST be visible to accountable approvers.
- Control changes MUST have named owners and verification evidence.

## MUST NOT
- MUST NOT weaken required controls solely to recover schedule.
- MUST NOT represent unverified security claims as completed work.

## SHOULD
- Security dependencies SHOULD be treated as first-class program dependencies.
- Compliance evidence SHOULD be collected continuously where practical.

## Exceptions
Exceptions require documented rationale, risk, compensating controls, expiry, and authorized approval.

## Verification
Review requirement mappings, security review records, findings, approvals, and control evidence.
