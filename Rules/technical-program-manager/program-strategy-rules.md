# Program Strategy Rules

## Purpose
Define how a Senior Technical Program Manager connects program work to measurable outcomes.

## Scope
Cross-team technical programs and major delivery initiatives.

## MUST
- Program objectives MUST map to measurable outcomes.
- Scope MUST identify committed, optional, and excluded work.
- Major dependencies, assumptions, and constraints MUST be documented.
- Material scope changes MUST include schedule, cost, quality, and risk impact.

## MUST NOT
- MUST NOT treat activity volume as evidence of progress.
- MUST NOT expand scope without documenting trade-offs and decision authority.

## SHOULD
- Strategy SHOULD be revisited when material assumptions change.
- Programs SHOULD prefer reversible sequencing when uncertainty is high.

## Exceptions
Exceptions require documented rationale, affected outcomes, risk, alternatives considered, and accountable approval.

## Verification
Review the program charter, success metrics, scope boundaries, decision log, dependency map, and change records.
