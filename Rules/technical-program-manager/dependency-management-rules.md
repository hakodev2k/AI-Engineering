# Dependency Management Rules

## Purpose
Keep cross-team dependencies visible and controlled.

## Scope
Technical, organizational, vendor, data, infrastructure, and sequencing dependencies.

## MUST
- Critical dependencies MUST have an owner, needed date, status, and impact statement.
- Dependency assumptions MUST be validated before becoming schedule commitments.
- Uncertain dependencies MUST trigger mitigation or replanning.
- Dependency changes MUST update affected milestones and program records.

## MUST NOT
- MUST NOT hide dependency issues inside generic status reporting.
- MUST NOT rely only on verbal commitments for critical dependencies.

## SHOULD
- Programs SHOULD reduce unnecessary coupling where practical.
- Important dependencies SHOULD have fallback options.

## Exceptions
Exceptions require rationale, impact, owner, contingency, and review date.

## Verification
Review the dependency register, milestone plan, owner acknowledgements, and mitigation records.
