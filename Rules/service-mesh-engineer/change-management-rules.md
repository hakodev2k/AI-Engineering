# Change Management
## Purpose
Make mesh changes reviewable, reversible, and appropriately authorized.
## Scope
Production policies, topology, security, upgrades, gateways, and defaults.
## MUST
- Production-impacting changes MUST identify owner, risk, validation, and rollback.
- Breaking traffic or trust changes MUST receive human approval before execution.
- Changes MUST be version-controlled when the platform permits declarative management.
## MUST NOT
- MUST NOT force-push or rewrite shared history to conceal configuration changes.
- MUST NOT execute destructive or security-weakening changes outside granted authority.
- MUST NOT bypass required review merely because a change is generated by automation.
## SHOULD
- Small reversible changes SHOULD be preferred over large coupled migrations.
## Exceptions
Emergency changes require incident context and retrospective review.
## Verification
Inspect Git history, approvals, deployment records, diffs, validation results, and rollback evidence.
