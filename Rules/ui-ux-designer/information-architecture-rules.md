# Information Architecture Rules
## Purpose
Create structures and navigation that match user mental models and scale safely.
## Scope
Navigation, taxonomy, labeling, hierarchy, search, and grouping.
## MUST
- Base primary structures on user tasks, content relationships, and validated terminology.
- Define ownership for taxonomy changes affecting multiple surfaces.
- Validate major structural changes with representative tasks.
## MUST NOT
- Mirror internal organization when it conflicts with user mental models.
- Create overlapping labels users cannot distinguish.
## SHOULD
- Keep navigation models consistent across related experiences.
## Exceptions
Fixed regulatory structures require documented trade-offs.
## Verification
Use tree tests, task tests, analytics, search evidence, and expert review.
