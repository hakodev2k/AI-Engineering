# Content Design Rules
## Purpose
Make interface language clear, actionable, consistent, and safe.
## Scope
Labels, instructions, errors, confirmations, empty states, and help.
## MUST
- Use terminology users understand consistently.
- Explain errors by what happened, what can be done, and irreversible consequences.
- Put critical conditions before commitment when they affect consent, cost, data, or access.
## MUST NOT
- Blame users for system failures or use manipulative urgency.
- Hide material terms in secondary content.
## SHOULD
- Prefer concise active language while preserving context.
## Exceptions
Fixed legal text may remain, but surrounding content must clarify the action.
## Verification
Run content review, terminology checks, localization stress tests, and usability validation.
