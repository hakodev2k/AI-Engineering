# Design Validation Rules
## Purpose
Require evidence before consequential design claims and release recommendations.
## Scope
Research, experiments, analytics, usability evidence, and design review.
## MUST
- Match evidence strength to decision risk and state confidence and limitations.
- Define success and failure criteria before evaluative tests where practical.
- Preserve negative and contradictory evidence.
- Revalidate when implementation changes invalidate tested behavior.
## MUST NOT
- Treat confidence or stakeholder approval as user evidence.
- Claim improvement without a relevant baseline when comparative.
## SHOULD
- Combine qualitative and quantitative evidence for high-impact decisions.
## Exceptions
Low-risk reversible changes may use post-release validation with rollback criteria.
## Verification
Review evidence, criteria, limitations, implementation fidelity, and decision traceability.
