# Problem Framing Rules

## Purpose
Prevent teams from optimizing an unverified or incorrectly framed problem.
## Scope
Problem statements, opportunity framing, design briefs, and early discovery.
## MUST
- Define affected users, context, current behavior, desired outcome, constraints, and supporting evidence.
- Distinguish the problem from proposed solutions.
- Identify assumptions that could invalidate the framing and define how they will be tested.
- Reframe when new evidence materially changes the problem.
## MUST NOT
- Treat stakeholder preference as user need without validation.
- lock a solution before critical problem uncertainty is bounded.
## SHOULD
- Express success in observable user and business outcomes.
## Exceptions
Compliance-mandated changes may constrain solution space but still require user-impact framing.
## Verification
Review the brief for evidence, assumptions, outcomes, constraints, and absence of embedded solution bias.
