# Documentation and Education Rules

## Purpose
Make educational material accurate, discoverable, task-oriented, and appropriate for the target developer audience.

## Scope
Applies to tutorials, guides, workshops, curricula, learning paths, and documentation contributions.

## MUST
- Material MUST define the user goal, prerequisites, expected outcome, and validation steps.
- Conceptual explanations MUST distinguish required behavior from recommended practice.
- Tutorials MUST be executable in the order presented and MUST not depend on undocumented setup.
- Broken or outdated high-traffic material MUST be corrected, redirected, or clearly marked.

## MUST NOT
- MUST NOT optimize for content volume at the expense of technical correctness.
- MUST NOT assume hidden environment state that prevents a clean-start reproduction.
- MUST NOT copy unsupported guidance into new material merely for consistency.

## SHOULD
- Educational paths SHOULD progress from core concepts to production concerns.
- Examples SHOULD explain important trade-offs rather than only the happy path.

## Exceptions
Intentional omission of advanced detail is acceptable when scope is explicit and a reliable next-step reference is provided.

## Verification
Follow the material from a clean setup, verify links and commands, review prerequisites, and confirm the stated outcome can be reproduced.
