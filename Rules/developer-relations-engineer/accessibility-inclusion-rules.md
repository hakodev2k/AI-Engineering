# Accessibility and Inclusion Rules

## Purpose
Make developer education and community participation usable by people with varied abilities, backgrounds, devices, and experience levels.

## Scope
Applies to events, documentation, videos, code samples, community programs, and digital content.

## MUST
- Published material MUST follow applicable accessibility requirements for the delivery format.
- Essential visual information MUST have an equivalent textual explanation where practical.
- Videos used as durable learning resources MUST provide captions or equivalent accessible transcripts.
- Participation rules and moderation MUST prohibit harassment and discriminatory exclusion.

## MUST NOT
- MUST NOT rely exclusively on color, audio, or pointer interaction to convey essential information when alternatives are feasible.
- MUST NOT treat accessibility feedback as cosmetic when it blocks task completion.
- MUST NOT use exclusionary language that unnecessarily narrows who can participate.

## SHOULD
- Examples SHOULD use readable formatting and explain assumed background knowledge.
- Event plans SHOULD consider captioning, venue access, remote participation, and sensory constraints.

## Exceptions
Temporary limitations require a documented remediation path and communication of the accessible alternative.

## Verification
Run accessibility checks where available, review captions and text alternatives, inspect event accommodations, and test critical learning paths with assistive workflows when practical.
