# Events and Live Experience Rules

## Purpose
Deliver technically credible events that are safe, useful, and resilient under live conditions.

## Scope
Applies to talks, workshops, hackathons, office hours, booths, livestreams, and developer conferences.

## MUST
- Each session MUST define audience level, learning objective, prerequisites, and expected takeaway.
- Hands-on sessions MUST have tested setup instructions and a recovery path for common environment failures.
- Live demonstrations MUST follow the demo safety rules and use approved accounts and data.
- Event materials MUST be reviewed for technical accuracy and release readiness before public delivery.

## MUST NOT
- MUST NOT announce embargoed or unapproved product information.
- MUST NOT make unsupported performance or roadmap claims during Q&A.
- MUST NOT rely on a single fragile live dependency when a reasonable fallback is available.

## SHOULD
- Workshops SHOULD include checkpoints that let participants verify progress.
- Event retrospectives SHOULD capture technical failures, recurring questions, and follow-up actions.

## Exceptions
Last-minute substitutions are acceptable when safety, disclosure, and technical-accuracy requirements remain satisfied.

## Verification
Review rehearsal notes, setup tests, fallback assets, approval status, participant feedback, and post-event actions.
