# Test Strategy Rules

## Purpose
Ensure testing is risk-driven and aligned with product, architecture, and release risk.
## Scope
Test planning across functional and non-functional quality.
## MUST
- Define test objectives, scope, risks, test levels, environments, evidence, and exit criteria before high-risk releases.
- Prioritize coverage using business impact, likelihood, change surface, and failure cost.
- Trace critical risks to concrete test activities.
## MUST NOT
- Treat test case count or pass percentage alone as proof of quality.
- Declare adequate coverage without identifying material untested risks.
## SHOULD
- Revisit strategy when architecture, scope, incidents, or production evidence changes.
## Exceptions
Abbreviated strategy requires documented risk, owner, compensating checks, and approval.
## Verification
Review risk-to-test traceability, exit criteria, release evidence, and unresolved gaps.
