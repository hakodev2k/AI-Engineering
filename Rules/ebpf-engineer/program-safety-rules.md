# eBPF Program Safety

## Purpose
Prevent unsafe or unverifiable eBPF programs from reaching production.

## Scope
All eBPF programs, loaders, generated bytecode, maps, helpers, and attach points.

## MUST
- Programs MUST pass the target kernel verifier before deployment.
- Every pointer dereference MUST satisfy verifier-visible bounds and provenance constraints.
- Loops MUST have bounded termination that is evident to the verifier.
- Program size, stack use, and helper use MUST remain within target-kernel limits.
- Failure to load or attach MUST fail safely and preserve diagnostic evidence.

## MUST NOT
- MUST NOT bypass verifier failures by weakening host security controls.
- MUST NOT assume behavior validated on one kernel is valid on all supported kernels.
- MUST NOT ship bytecode whose source, build inputs, and target compatibility cannot be traced.

## SHOULD
- Prefer simple verifier-friendly control flow over clever constructs.
- Keep privileged program scope minimal.

## Exceptions
Any exception requires documented reason, affected kernels, risk, alternative considered, validation evidence, rollback plan, and human approval for production impact.

## Verification
Run verifier/load tests on every supported kernel class; inspect verifier logs, CI artifacts, bytecode metadata, and negative-path tests.
