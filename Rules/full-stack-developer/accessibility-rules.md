# Accessibility Rules

## Purpose
Ensure user-facing functionality remains usable by people with diverse access needs.
## Scope
Semantic UI, keyboard use, focus, forms, dynamic content, and visual presentation.
## MUST
- Use semantic controls and accessible names for interactive elements.
- Preserve keyboard operability and visible, logical focus behavior.
- Associate errors and instructions with relevant controls.
## MUST NOT
- Encode essential meaning only through color or pointer interaction.
- Remove accessibility semantics to simplify styling.
## SHOULD
- Test critical journeys with automated checks plus keyboard and assistive-technology review where warranted.
## Exceptions
Known accessibility gaps require documented impact, owner, remediation plan, and approval when release risk is material.
## Verification
Automated accessibility scans, keyboard tests, semantic inspection, and targeted screen-reader review.
