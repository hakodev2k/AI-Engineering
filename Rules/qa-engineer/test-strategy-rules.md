# Test Strategy Rules
## Purpose
Define risk-based verification that protects product quality across the delivery lifecycle.
## Scope
Test planning, coverage, execution, and release evidence.
## MUST
- Derive test scope from business impact, technical risk, change surface, and failure history.
- Define test levels, owners, environments, entry/exit criteria, and required evidence for material releases.
- Map critical risks to explicit verification activities.
## MUST NOT
- Treat test-case count or pass percentage alone as evidence of adequate quality.
- Apply identical depth to low-risk and safety-critical changes without justification.
## SHOULD
- Reassess strategy when architecture, usage, incidents, or release model changes.
## Exceptions
Reduced scope requires documented risk, compensating controls, and accountable approval.
## Verification
Review risk-to-test traceability, release criteria, coverage gaps, and post-release defect evidence.
