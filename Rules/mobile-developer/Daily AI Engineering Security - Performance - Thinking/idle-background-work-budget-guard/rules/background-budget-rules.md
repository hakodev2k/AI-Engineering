# Background Budget Rules
- Every recurring/background job MUST declare an owner, trigger, minimum interval, cancellation behavior, and idle/active eligibility.
- Performance changes MUST begin with a measured baseline.
- Idle CPU MUST be evaluated in core-time or equivalent normalized units, not only total-system percentage.
- Jobs MUST NOT overlap with another instance unless overlap is explicitly safe and budgeted.
- Repeated full scans of unchanged state SHOULD be replaced with watermarks/change detection when correctness permits.
- A job that breaches its configured wall-time/resource budget repeatedly MUST enter defer/cancel/recovery rather than restart indefinitely.
- Retry loops MUST be bounded and MUST use backoff or a circuit-break condition.
- Hidden/minimized/idle state SHOULD reduce non-urgent work, but required security/integrity work MUST NOT be disabled solely for performance.
- Optimization MUST NOT weaken data integrity, permission checks, sandboxing, or required synchronization.
- Completion MUST include before/after metrics and correctness evidence.
- The component implementing a scheduling change MUST NOT be the only verifier.
- Unknown job ownership or unsafe cancellation semantics MUST block automatic termination.
