# Runtime Ownership and Reaping Rules

- Every managed subprocess or local runtime MUST be registered with an owner id, runtime key, PID, and process start time before it is considered ready.
- Cleanup MUST validate both PID and start time; PID alone MUST NOT establish identity.
- The guard MUST NOT terminate a process that is not present in the ownership registry with matching identity.
- The guard MUST NOT terminate processes by executable name, command substring, or parent PID alone.
- Equivalent shareable stdio MCP runtimes SHOULD be reused when their configuration/permission fingerprint is unchanged and health checks pass.
- A new spawn MUST be blocked when the configured hard process budget would be exceeded unless a safely identified stale resource is reconciled first.
- Legitimate parallel owners MUST NOT be collapsed merely to reduce process count.
- Owner terminal events MUST trigger reconciliation within the configured grace window.
- Shared runtimes MUST remain alive while at least one registered active owner still references them.
- Graceful termination MUST be attempted before forced termination unless the child is known to be unsafe or already unresponsive beyond the grace deadline.
- Forced termination MUST be bounded to one attempt per process identity and MUST be followed by exit verification.
- A cleanup cycle MUST have a maximum of two reconciliation passes.
- The guard MUST record spawn, reuse, cleanup, and orphan metrics without recording secret-bearing environment values.
- Performance improvement MUST NOT be claimed without the same before/after repeated-turn benchmark.
- Completion MUST be blocked if terminal owners retain owned non-shared processes after the final grace period.
- Completion MUST be blocked if an unregistered or PID-reused process would need to be killed to satisfy the budget.
- The system SHOULD reserve headroom below OS exhaustion; hard limits are safety gates, not target utilization.
- Persistent restore state SHOULD have a TTL or explicit terminal-state check before recreating a runtime.
- Any destructive or system-wide cleanup outside registered agent-owned processes MUST require explicit human approval.
