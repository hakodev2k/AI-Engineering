# Client Impact Note

## Change
Describe the changed operation/schema precisely.

## Compatibility classification
Choose one: additive-compatible / behavior-risk / breaking.

## Evidence
List OpenAPI paths, schema fields, generated-client/test output, and relevant implementation references.

## Affected consumers
Identify known clients or state that consumers are unknown.

## Migration action
Describe client/server changes, deprecation period, versioning strategy, or compatibility shim.

## Approval
For a breaking contract, record the explicit human approval reference before implementation or release.

## Verification
Record final drift-report status, tests/client builds executed, and remaining risks.
