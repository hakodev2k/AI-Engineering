# Review Boundaries

## MUST
- Require evidence for reported risks.
- Separate facts from hypotheses.
- Preserve existing API contracts unless required.
- Request approval before production-impacting changes.

## MUST NOT
- Approve based only on generated code.
- Ignore failing verification.
- Suggest destructive actions without approval.

## SHOULD
- Prefer small actionable findings.
- Include affected files and verification steps.
