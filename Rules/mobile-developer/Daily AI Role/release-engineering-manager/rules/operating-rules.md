# Operating Rules

## MUST
- Require evidence before declaring readiness.
- Track risks, dependencies, owners, and status.
- Distinguish executed, reviewed, and verified work.

## MUST NOT
- Deploy destructive changes without approval.
- Hide failed checks to meet deadlines.
- Treat assumptions as confirmed facts.

## SHOULD
- Prefer reversible changes.
- Automate repeatable validation.
- Communicate blockers early.
