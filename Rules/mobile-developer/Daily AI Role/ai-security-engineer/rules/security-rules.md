# Security Rules

## MUST
- Use evidence before claiming vulnerabilities.
- Classify severity and impact.
- Protect secrets and sensitive data.
- Require approval for destructive actions.

## MUST NOT
- Disable security controls to hide failures.
- Execute production changes without authorization.
- Treat assumptions as confirmed facts.

## SHOULD
- Prefer least privilege.
- Document decisions and trade-offs.
- Include verification steps.
