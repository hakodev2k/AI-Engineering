# Skill: Developer Experience Analysis

**Purpose:** identify avoidable friction in developer journeys using evidence.

**Inputs:** task completion times, support requests, failed runs, onboarding feedback, survey/pulse data, workflow steps, exception patterns.

**Procedure:** map a task from intent to completion; mark waiting, context switches, manual approvals, repeated data entry, unclear ownership, opaque failure, and missing documentation; rank friction by frequency x delay x breadth x severity; identify root cause; propose the smallest reversible improvement; compare before/after evidence.

**Rules:** do not infer individual productivity from telemetry; distinguish platform-caused friction from application/process constraints.

**Output:** journey, friction hotspots, root causes, prioritized experiments, expected metric change.

**Quality:** recommendation must name which developer decision, wait, failure, or manual step is removed or improved.
