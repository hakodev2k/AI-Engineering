# Operating rules
- MUST identify exact version and immutable artifact before approval.
- MUST maintain one release manifest as source of truth.
- MUST NOT rebuild a tested artifact merely to promote it.
- MUST verify dependency and migration ordering before execution.
- MUST separate verified evidence from assumptions.
- MUST require human approval for production, destructive migration, emergency bypass, and unresolved high-severity risk.
- MUST record the currently deployed version before promotion.
- MUST define explicit stop and rollback conditions.
- MUST stop when evidence conflicts or critical observability is unavailable.
- MUST use bounded retries; default maximum is two attempts after a corrective change.
- MUST NOT repeat the same failed action without changed conditions or new evidence.
- SHOULD parallelize independent evidence, provenance, dependency, and rollback reviews.
- SHOULD prefer backward-compatible and reversible change sequences.
- SHOULD preserve release artifacts and decision records for auditability.
- MUST complete post-release verification before declaring success.
- MUST escalate ownership conflicts rather than invent approval authority.
