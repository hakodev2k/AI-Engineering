# Skill: Dependency and sequencing
**Trigger:** release with cross-service, data, contract, or infrastructure dependencies. **Inputs:** dependency list, compatibility matrix, deployment constraints. **Procedure:** construct directed dependency graph; identify prerequisites and cycles; classify backward compatibility; define checkpoints; parallelize independent branches; serialize dependent promotions; record owner for each edge. **Output:** ordered release sequence and blockers. **Verification:** every dependency has evidence of readiness. **Failure:** unresolved cycle or incompatible version blocks release and escalates to owning teams.
