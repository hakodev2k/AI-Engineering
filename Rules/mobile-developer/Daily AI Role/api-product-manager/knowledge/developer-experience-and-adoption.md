# Developer Experience and Adoption

API adoption is a funnel: discover → understand → authenticate → first successful call → complete real task → operate reliably → expand usage.

Measure friction at each stage. Useful signals include time-to-first-success, task completion, integration lead time, error rate by consumer, documentation search/support volume, migration completion, retained active consumers, feature adoption, and cost per successful task.

Documentation should provide concepts, authentication, quickstart, reference, realistic examples, error handling, limits, lifecycle/version policy, changelog, and migration guidance.

Do not optimize adoption by hiding important constraints. Good DX makes constraints predictable and actionable.

When metrics disagree, investigate cohorts and task-level outcomes before drawing conclusions.
