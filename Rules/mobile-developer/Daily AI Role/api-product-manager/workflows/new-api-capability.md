# Workflow: New API Capability

**Trigger:** validated or candidate consumer need. **Goal:** decide and prepare a trustworthy new API capability.

## Stages
1. Intake and consumer discovery — API PM.
2. Problem/evidence validation — API PM + Consumer DX Reviewer.
3. Product contract proposal — API PM.
4. Parallel reviews — compatibility, security/governance, DX, economics/adoption.
5. Consolidation — API PM resolves conflicts or escalates authority gaps.
6. Prioritization/roadmap — define owner, dependency, milestone, success metric.
7. Engineering handoff — use product brief and contract acceptance criteria.
8. Readiness checkpoint — invoke launch workflow when implementation evidence exists.

## Dependencies
Do not finalize a contract before critical security/architecture constraints are known. Parallel reviews start only after shared contract context is stable.

## Retry/failure
Transient tool retry max 2. Missing critical evidence or unresolved high-risk conflict stops commitment and escalates.

## DoD
Problem evidence, contract recommendation, reviews, risks, dependencies, roadmap decision, handoff, metrics, and required approvals are complete.
