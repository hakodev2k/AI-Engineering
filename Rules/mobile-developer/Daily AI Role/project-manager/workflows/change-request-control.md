# Workflow: Change Request Control

**Trigger:** material change request.
**Goal:** decide change transparently without losing baseline integrity.

1. Register request and requester evidence.
2. Identify affected baseline/version.
3. Parallel impact analysis: scope; schedule/critical path; cost/capacity; RAID; dependencies; acceptance/quality.
4. Synchronize findings and resolve contradictory assumptions.
5. PM prepares options, recommendation and no-change consequence.
6. Human decision gate by authorized approver.
7. If approved: version baseline, update dependencies/RAID/milestones and communicate.
8. If rejected/deferred: preserve record and rationale.
9. Verify downstream plans and handoffs reflect the decision.

**Retry:** max 3 evidence-gathering cycles.
**DoD:** decision traceable; baseline unchanged unless approved; consequences communicated.
