# Skill: Change Control

**Purpose:** evaluate and govern changes without silently corrupting the baseline.

**Trigger:** request affecting approved scope, date, budget, quality gate, dependency or contractual assumption.

**Steps:** log request and source; locate affected baseline; run scope/schedule/cost/risk/dependency impact analysis in parallel where independent; identify alternatives including no-change; state recommendation and confidence; identify approver; record approve/reject/defer; update baseline only after approval; communicate consequences and traceability.

**Constraints:** stakeholder urgency is not approval. No budget/date/contract commitment without authorized human approval.

**Output:** decision record and, if approved, updated baseline/version links.

**Failure:** if impact cannot be bounded, mark decision blocked and escalate rather than guessing.
