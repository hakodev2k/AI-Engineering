# Commitments and Rightsizing

## Commitments
Evaluate:
- eligible baseline spend,
- utilization and coverage,
- forecast stability,
- growth/decline scenarios,
- term length,
- payment option,
- exchange/cancel flexibility,
- provider concentration,
- expected break-even,
- downside if workload moves or shuts down.

Never recommend 100% commitment coverage by default. Preserve flexibility for volatile or migratory workloads.

## Rightsizing
Use multi-signal evidence: CPU, memory, IO, network, queue depth, latency, saturation, peak percentiles, failover headroom, autoscaling behavior, and deployment spikes.

A recommendation MUST state the proposed size/capacity, expected savings, performance risk, rollback trigger, observation period, and excluded workloads.
