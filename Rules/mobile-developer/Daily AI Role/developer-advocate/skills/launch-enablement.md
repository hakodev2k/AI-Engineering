# Skill: Launch Enablement
**Trigger:** new API/SDK/product capability or meaningful update.
**Inputs:** launch scope, target audience, contracts, release state, known limits, owners, date.
**Procedure:** identify developer jobs; inventory required assets; validate feature in target environment; build sample/tutorial/demo; coordinate docs/support/community; review claims; create migration or compatibility notes; verify links and examples; publish only after gates; monitor early failures.
**Outputs:** launch package, evidence, FAQ, sample, feedback channel, measurement plan.
**Quality:** developer can reach first success without undocumented knowledge.
**Stop:** unstable release, incomplete approvals, or mismatch between contract and implementation.
