# Workflow: Launch Enablement
**Trigger:** approved product/API/SDK launch.
**Goal:** developers can discover and successfully use the capability at launch.
**Inputs:** launch brief, contracts, audience, owners, deadline, known limitations.
**Preconditions:** release scope and supported behavior are stable enough to verify.
**Stages:** intake → audience/jobs → parallel asset plan + sample build + dependency review → fact/security review → clean-run verification → publication approval → launch → early-signal monitoring → handoff.
**Parallel:** sample, outline, FAQ draft, channel plan after facts stabilize.
**Checkpoint:** no claim mismatch, broken sample, missing approval, or critical security issue.
**Retry:** max 2 correction cycles per failed review.
**Failure:** block publication and escalate unresolved contract/release mismatch.
**DoD:** launch assets verified, owners ready, feedback channel active, metrics defined.
