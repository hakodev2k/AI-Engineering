# Workflow: Demo and Evaluation

**Trigger:** Customer needs product evidence but not a full POC.
**Goal:** Demonstrate relevant workflow accurately.

## Stages
1. Select customer decision criteria and narrative.
2. Prepare environment, data, identities, integrations, and fallback evidence.
3. Review claims against sources; security review if sensitive.
4. Rehearse deterministic path and failure recovery.
5. Run demo; capture questions and deviations.
6. Map observed evidence to criteria.
7. Follow up with answers, gaps, and next action.

**Parallel:** Environment setup and evidence/claim review may run in parallel after scenario is fixed.
**Checkpoint:** No unverified claim enters the spoken script as fact.
**Retry:** At most one same-session retry for a transient demo issue; otherwise use approved fallback and investigate afterward.
**Escalation:** Product/security/engineering owner for unresolved material capability claims.
**DoD:** Customer saw decision-relevant evidence; questions and limitations are recorded and owned.
