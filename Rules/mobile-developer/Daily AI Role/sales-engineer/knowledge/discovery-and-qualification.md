# Discovery and Qualification

Good technical discovery establishes why change matters, how the current system works, what must be true for adoption, and how the customer will decide.

Use five lenses:
1. Outcome: measurable business/user result.
2. Workflow: current actors, systems, handoffs, failure points.
3. Technical environment: architecture, identity, network, data, APIs, scale, operations.
4. Decision: stakeholders, criteria, process, timeline, alternatives.
5. Risk: security, privacy, compliance, migration, lock-in, performance, support.

Classify requirements as must-have, should-have, optional, or unknown priority. Never infer urgency from enthusiasm alone. A qualified technical problem has an owner, measurable pain/outcome, plausible solution path, known decision criteria, and a next action.
