# UX Reasoning Principles

- Start with user task and outcome, not a preferred screen or feature.
- Separate observed evidence, stakeholder belief, design hypothesis, and decision.
- Optimize critical task success before aesthetic novelty.
- Make system status visible and actions predictable.
- Prefer prevention over error messaging; preserve user work when recovery is possible.
- Reduce memory burden by exposing needed context at the point of action.
- Use progressive disclosure where complexity is conditional.
- Design for real states: loading, empty, partial, error, timeout, permission, conflict, interruption, retry, cancellation, success.
- Treat irreversible actions with stronger confirmation, explanation, and recovery when possible.
- Validate high-risk assumptions early with the cheapest credible method.
- Use consistency deliberately, but allow divergence when user context materially differs.
- Never convert anecdote into prevalence without data.
