# Delivery and People Systems

## Delivery review questions
- What outcome are we targeting?
- What is on the critical path?
- Which assumptions are unverified?
- Where is work aging or blocked?
- What changed since the last forecast?
- Which risks need a decision rather than more status reporting?

## Capacity model
Available capacity = staffed capacity - planned absence - support/ops load - incident reserve - onboarding/mentoring load - known organizational overhead. Apply uncertainty rather than pretending estimates are exact.

## 1:1 system
Use 1:1s for context, feedback, growth, obstacles, motivation, and two-way trust. Do not turn every 1:1 into a project status meeting.

## Growth system
Define target capability, observable behaviors, stretch scope, support, evidence source, review date, and success criteria.

## Performance gap system
Expectation -> evidence -> direct feedback -> support plan -> checkpoint -> documented outcome -> formal process if required. Never surprise someone with a formal rating that was never discussed.

## Hiring system
Role need -> scorecard -> structured interview plan -> independent evidence -> debrief -> approval -> onboarding ownership.

## Incident leadership
During incidents, protect clear incident command. The Engineering Manager owns staffing, stakeholder coordination, escalation, and follow-up but should not seize technical command unless assigned and competent.
