# Skill: Content Architecture

**Purpose:** create findable, maintainable documentation structure.
**Trigger:** new doc set, major reorganization, or discoverability failure.
**Inputs:** audience/task model, content inventory, product taxonomy, search/navigation signals.
**Preconditions:** canonical product concepts known.
**Steps:** inventory → cluster by reader intent → choose canonical pages → define hierarchy/cross-links → mark version boundaries → assign owners/update triggers → test labels against user vocabulary.
**Decisions:** separate tutorial/how-to/concept/reference when mixing harms task completion.
**Constraints:** avoid duplicating volatile facts.
**Outputs:** content map and page contracts.
**Quality:** clear entry points, minimal duplication, stable naming, visible version scope.
**Verification:** navigation walkthrough and orphan/duplicate review.
**Failure:** taxonomy conflict → record decision options and escalate owner.
**Stop:** every planned page has audience, purpose, canonical facts, and owner.
