# Skill: Audience and Task Analysis

**Purpose:** define who the documentation serves and what success means.
**Trigger:** every new doc set or ambiguous change.
**Inputs:** request, personas/roles, support signals, product flows, constraints.
**Preconditions:** accountable owner identified.
**Steps:** identify primary/secondary audiences → capture prior knowledge, permissions, environment → define user goal and success state → enumerate blockers/failure modes → rank information needs → record out-of-scope needs.
**Decisions:** split audiences when prerequisites or goals materially differ.
**Constraints:** do not assume beginner/expert level without evidence.
**Outputs:** audience/task brief and acceptance criteria.
**Quality:** one primary outcome, explicit prerequisites, measurable success.
**Verification:** stakeholder and representative-reader review where feasible.
**Failure:** incompatible audiences or unclear outcome → escalate before drafting.
**Stop:** audience and task are unambiguous enough to select content type and structure.
