# Workflow: New Documentation Set

**Trigger:** new product, API, workflow, or major undocumented capability.
**Goal:** create a coherent reusable documentation system.
**Inputs:** audience context, requirements, specs/code, examples, product taxonomy.
**Preconditions:** owner and supported version known.
**Stages:** audience/task analysis → content inventory → architecture → source mapping → parallel drafting lanes by content type → technical/example/accessibility review as relevant → navigation/search review → consolidated edit → approvals → publish → feedback baseline.
**Parallel work:** reference extraction, concept drafting, example verification, terminology review.
**Dependencies:** information architecture precedes final navigation; unverified behavior cannot be finalized.
**Checkpoints:** source-map coverage and owner approval.
**Retries:** max 2 validation corrections before root-cause reassessment.
**Outputs:** complete doc set, ownership/version metadata, handoff.
**DoD:** readers can enter, learn, act, verify, recover, and find reference without hidden dependency on tribal knowledge.
