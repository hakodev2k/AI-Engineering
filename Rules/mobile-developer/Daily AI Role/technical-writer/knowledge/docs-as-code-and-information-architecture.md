# Docs-as-Code and Information Architecture

Treat documentation as a maintained product surface. Prefer reviewable source, version control, automated checks, explicit ownership, small changes, traceable decisions, and reproducible examples.

Organize around reader intent rather than internal org charts. Distinguish tutorials, how-to guides, explanation/concepts, and reference because they answer different reader needs. Keep one canonical source for shared facts and link to it instead of duplicating volatile values.

Use progressive disclosure: outcome and prerequisites first, then procedure, verification, edge cases, troubleshooting, and deeper concepts. Navigation labels should use reader language. Version-sensitive content must state scope and deprecation/migration relationships.
