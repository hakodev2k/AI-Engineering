# Documentation Quality and Evidence

Accuracy is evidence-backed correspondence with current system behavior. A polished sentence without a source is not proof.

Evidence strength, strongest first: executable test against supported system; authoritative specification/schema/code path; approved ADR/design; accountable SME confirmation; existing docs; inference. Inference must be labeled and cannot become a product promise.

Quality dimensions: task success, technical accuracy, completeness, clarity, findability, accessibility, maintainability, freshness, consistency, and safe failure guidance.

High-risk instructions require explicit prerequisites, permissions, blast radius, verification, rollback/recovery, and human approval where the operation is destructive or security sensitive.
