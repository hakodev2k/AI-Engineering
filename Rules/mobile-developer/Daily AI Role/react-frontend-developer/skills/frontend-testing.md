# Skill: Frontend Testing
Purpose: create risk-proportional regression protection. Trigger: behavior change or defect fix. Inputs: acceptance criteria, failure modes, component/API boundaries. Preconditions: observable behavior identified. Steps: rank risks; choose unit/component/integration/e2e layer; test user-observable behavior; include failure state and regression case; avoid mocking away the behavior under test; run targeted then broader suite. Decisions: lowest reliable layer that proves requirement. Constraints: no snapshot-only proof for critical behavior. Output: test set and execution evidence. Quality: deterministic, meaningful failures. Verification: demonstrate test fails for the original defect where practical. Failure: flaky test must be diagnosed or quarantined via approved process, not ignored. Stop: required risks have evidence.
