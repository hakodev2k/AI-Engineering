# React Engineering Principles
- Model UI as state transitions, not a collection of click handlers.
- Keep a single source of truth for each state; derive values instead of duplicating them.
- Prefer local state until cross-boundary sharing is justified.
- Component boundaries should follow cohesive behavior and change reasons, not arbitrary file size.
- Keep transport/API mapping at an integration boundary so views consume stable domain-shaped data.
- Effects synchronize with external systems; do not use them for values that can be computed during render.
- Treat server state, URL state, form state and ephemeral UI state as different concerns.
- Stable keys represent identity; indexes are unsafe when list order/membership changes.
- Error boundaries do not replace normal async error handling.
- Memoization is a measured optimization, not a default architecture strategy.
- Prefer explicit state machines or discriminated states when async flows have many transitions.
