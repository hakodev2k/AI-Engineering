# Security Risk Rules
## Purpose
Make security risk an explicit engineering-management responsibility.
## Scope
Security findings, access, secrets, dependencies, threat exposure, and remediation prioritization.
## MUST
- Ensure material security findings have severity, owner, remediation decision, and target date.
- Escalate unacceptable residual risk to authorized decision makers.
- Require least privilege and secure handling of credentials and sensitive data.
## MUST NOT
- Disable security controls merely to meet delivery dates.
- Accept material security risk without documented rationale and accountable approval.
## SHOULD
- Include security work in normal planning rather than treating it only as emergency work.
## Exceptions
Temporary compensating controls require expiry, monitoring, evidence, and approval.
## Verification
Review security findings, access reviews, remediation backlog, exceptions, scans, and approvals.
