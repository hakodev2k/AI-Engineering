# Problem Framing Rules
## Purpose
Ensure ML work solves a measurable product or operational problem.
## Scope
New models, major model changes, and ML-backed decisions.
## MUST
- Define the decision, target population, success metric, baseline, constraints, and failure cost before model development.
- Separate business outcomes from offline proxy metrics and document how they relate.
- Establish a non-ML baseline where practical.
## MUST NOT
- Start model selection before the prediction target and evaluation criteria are unambiguous.
- Treat model accuracy alone as proof of product value.
## SHOULD
- Prefer the simplest approach that satisfies measured requirements.
## Exceptions
Exceptions require rationale, risk, evidence, and reviewer approval.
## Verification
Review the problem statement, baseline, acceptance thresholds, experiment plan, and stakeholder sign-off.
