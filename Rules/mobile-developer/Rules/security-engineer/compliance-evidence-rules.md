# Compliance Evidence Rules

## Purpose
Ensure security-control claims are supported by reliable, reviewable evidence.

## Scope
Applies to audits, certifications, internal control reviews, customer assurance, and regulatory security obligations.

## MUST
- Control evidence MUST demonstrate actual implementation and operation, not only policy intent.
- Evidence MUST be attributable to a defined system, control owner, period, and scope.
- Material control failures MUST be reported accurately and tracked to remediation or accepted risk.
- Security attestations MUST be consistent with observable technical reality.
- Evidence containing sensitive information MUST be protected according to its classification.

## MUST NOT
- MUST NOT fabricate, alter, or selectively omit evidence to create a misleading control conclusion.
- MUST NOT treat a passed audit as proof that all security risks are controlled.
- MUST NOT expose secrets or unnecessary sensitive data in evidence packages.

## SHOULD
- Prefer automatically generated, reproducible evidence for repeatable controls.
- Keep control mappings traceable to technical implementation and ownership.

## Exceptions
Manual evidence is acceptable when automation is impractical, provided collection steps and reviewer expectations are documented.

## Verification
Use audit trails, configuration exports, access reports, test results, change records, tickets, telemetry, and independent review.
