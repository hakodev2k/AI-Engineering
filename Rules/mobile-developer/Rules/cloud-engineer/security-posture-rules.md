# Security Posture Rules
## Purpose
Maintain secure cloud defaults and measurable security posture.
## Scope
Cloud configuration, vulnerability exposure, posture management, policy findings, and remediation.
## MUST
- Security-critical cloud controls MUST have defined owners and remediation expectations.
- Material findings MUST be triaged using exploitability, exposure, asset criticality, and business impact.
- Security claims MUST be supported by configuration inspection, tests, scans, or equivalent evidence.
## MUST NOT
- MUST NOT suppress findings merely to improve compliance scores.
- MUST NOT weaken security controls to unblock delivery without explicit risk acceptance.
## SHOULD
- Automate secure baselines and drift detection where practical.
## Exceptions
Risk acceptance requires affected assets, threat, compensating controls, expiry/review date, and authorized approval.
## Verification
Inspect posture findings, policy compliance, vulnerability reports, exceptions, remediation evidence, and configuration history.
