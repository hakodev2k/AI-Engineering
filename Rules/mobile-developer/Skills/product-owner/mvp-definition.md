# MVP Definition

## Purpose
Define the smallest coherent product increment that can test a material value hypothesis or deliver a necessary outcome without disguising incomplete quality as minimalism.

## When to use
Use for new products, major capabilities, uncertain opportunities, pilots, and scope reduction.

## Inputs
Target problem, user segment, value hypothesis, risks, candidate capabilities, quality constraints, and learning goals.

## Context to inspect
Inspect current alternatives, critical user journey, adoption barriers, irreversible dependencies, security/privacy needs, and measurement capability.

## Core knowledge
An MVP is minimum viable evidence or value, not simply fewer tickets. Viability includes trust, safety, usability, and the ability to learn from real behavior.

## Procedure
1. State the target user and problem.
2. Define the value or learning hypothesis.
3. Identify the minimum end-to-end journey.
4. Remove secondary personas, variants, and conveniences.
5. Preserve mandatory safety, security, data, and reliability controls.
6. Decide what can be manual or operationally supported temporarily.
7. Define success and failure signals.
8. Establish rollout boundaries and support plan.
9. Validate that the MVP can answer the intended question.
10. Plan explicit follow-up decisions based on evidence.

## Decision points
Use a prototype when usability is the main unknown; a concierge/manual workflow when process value is unknown; production MVP when real usage is required.

## Common failure patterns
Calling a low-quality release an MVP, testing too many assumptions, no measurement, building platform infrastructure before validating value, and retaining every stakeholder request.

## Verification
The scope is end-to-end, safe enough for intended exposure, measurable, and smaller than the full solution while still testing the core hypothesis.

## Expected output
An MVP scope with hypothesis, included journey, exclusions, quality boundaries, metrics, and next decision.

## Stop conditions
Stop when minimum scope cannot meet mandatory safety, legal, security, or contractual requirements.
