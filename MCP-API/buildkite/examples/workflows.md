# Buildkite Connector Workflow Examples

These examples contain no credentials. Approval tokens are generated by a trusted application outside the model and bound to the exact tool intent.

## Investigate a failing build

1. `buildkite.build.list`
   - Input: `{"org_slug":"acme","pipeline_slug":"web","state":"failing","per_page":10}`
   - Permission: `read_builds`
   - Risk: READ
   - Approval: no
   - Output: build summaries.
2. `buildkite.job.list`
   - Input: `{"org_slug":"acme","pipeline_slug":"web","build_number":"42"}`
   - Permission: `read_builds`
   - Risk: READ
   - Approval: no
   - Output: jobs and states.
3. `buildkite.logs.search`
   - Input: `{"org_slug":"acme","pipeline_slug":"web","build_number":"42","job_id":"job-uuid","pattern":"error|failed","context":5}`
   - Permission: `read_build_logs`
   - Risk: READ
   - Approval: no
   - Output: matching log entries with context.

## Trigger a build after review

Tool: `buildkite.build.create`

Input before approval:

```json
{
  "org_slug": "acme",
  "pipeline_slug": "web",
  "commit": "0123456789abcdef",
  "branch": "main",
  "message": "Validated release candidate"
}
```

Permission: `write_builds`. Risk: WRITE. Approval: required. A trusted controller computes the HMAC approval token for the exact input and adds it as `approval_id` before invoking the tool. Expected output is the created build summary returned by Buildkite's official MCP server.

## Retry one failed job

Tool: `buildkite.job.retry`

Input: `{"org_slug":"acme","pipeline_slug":"web","build_number":"42","job_id":"job-uuid","approval_id":"<trusted-controller-generated-hmac>"}`

Permission: `write_builds`. Risk: WRITE. Approval: required. Expected output is the retried job/build response from the official Buildkite MCP server.

## Remove a sensitive artifact

Tool: `buildkite.artifact.delete`

Input: `{"org_slug":"acme","job_id":"job-uuid","artifact_id":"artifact-uuid","approval_id":"<trusted-controller-generated-hmac>"}`

Permission: `write_artifacts`. Risk: DESTRUCTIVE. Approval: required. This capability intentionally uses Buildkite REST because the official Buildkite MCP artifacts toolset exposes list/get operations but not artifact deletion. A successful response is `{"ok":true}`. For artifacts stored in customer-managed external storage, Buildkite documents that deletion from that external storage may need to be handled separately.
