# Inngest MCP/API Connector

Reusable MCP server for inspecting and operating Inngest durable workflows. It presents a stable, provider-scoped MCP tool surface, keeps credentials inside the connector, prefers Inngest's official Cloud MCP server, and falls back to the official REST API v2 for the implemented operations when MCP is unavailable or its live schema does not match the normalized call.

## Official sources researched

Research date: 2026-09-15.

- Inngest MCP: https://www.inngest.com/docs/ai-dev-tools/mcp
- REST API overview/OpenAPI: https://api-docs.inngest.com/ and https://api-docs.inngest.com/api-specs/v2.json
- Authentication: https://api-docs.inngest.com/authentication
- CLI/API mapping: https://www.inngest.com/docs/cli
- Cancellation semantics: https://www.inngest.com/docs/features/inngest-functions/cancellation

Inngest provides an official Cloud MCP endpoint at `https://api.inngest.com/mcp` authenticated with an Inngest API key. It also provides a local Dev Server MCP endpoint at `http://127.0.0.1:8288/mcp`. This connector intentionally targets Cloud; local development can connect directly to the Dev Server MCP.

The official Cloud MCP currently exposes tools for account/environments, apps/functions, events, runs/traces, sessions, webhooks, experiments, Insights and app sync. Inngest documents that eligible REST API v2 endpoints become MCP tools automatically, so clients should treat the live discovered schema as authoritative.

## Transport strategy

The connector prefers the official Cloud MCP for normalized capabilities whose discovered input schema is compatible. It uses a fixed allowlist and exact official origin, and it does not trust newly discovered upstream tools automatically. If the official MCP is unavailable or incompatible, the same external tool contract falls back to REST API v2 at `https://api.inngest.com/v2`.

REST fallback is implemented for all tools in this package. No arbitrary API-request tool is exposed.

## Authentication and least privilege

Set `INNGEST_API_KEY` to an API key created in Inngest Cloud. Inngest specifically recommends API keys for CI/CD, scripts and AI tools. The Cloud MCP accepts API keys, not signing keys. Environment-scoped API keys are preferred when the connector only needs one environment.

The key stays in the credential/client layer and is never accepted as a tool argument or returned to the model. The REST client sends `Authorization: Bearer <key>` only to the fixed official Cloud API origin.

## Tools and risk model

| Tool | Preferred transport | Risk | Approval |
|---|---|---:|---|
| `inngest.account.get` | MCP -> REST | READ | no |
| `inngest.environment.list` | MCP -> REST | READ | no |
| `inngest.app.list` | MCP -> REST | READ | no |
| `inngest.app.get` | MCP -> REST | READ | no |
| `inngest.function.list` | MCP -> REST | READ | no |
| `inngest.function.get` | MCP -> REST | READ | no |
| `inngest.run.list` | REST | READ | no |
| `inngest.run.get` | MCP -> REST | READ | no |
| `inngest.run.trace.get` | MCP -> REST | READ | no |
| `inngest.event.send` | MCP -> REST | HIGH_RISK | required |
| `inngest.function.invoke` | MCP -> REST | HIGH_RISK | required |
| `inngest.run.cancel` | MCP -> REST | HIGH_RISK | required |
| `inngest.run.rerun` | MCP -> REST | HIGH_RISK | required |

Event sending and function invocation are HIGH_RISK because deployed functions may send messages, change databases, charge accounts, deploy software, or perform other downstream effects. Cancellation changes workflow execution and rerun can repeat prior side effects, so both require explicit approval.

This connector does not expose environment mutation, app sync, webhook creation, signing/event key retrieval, Insights SQL, sandbox command execution, or other broader control-plane capabilities. This keeps default authority substantially narrower than the full upstream MCP surface.

## Approval behavior

READ tools may execute automatically. HIGH_RISK tools always require an opaque `approvalId` matching a connector-side grant held in `INNGEST_APPROVAL_TOKEN`. The grant is not an Inngest credential and should be injected by a trusted MCP host/approval UI, not generated by the model.

`INNGEST_REQUIRE_WRITE_APPROVAL` is retained for future WRITE-class tools; current mutations are all classified HIGH_RISK and therefore always require approval. Destructive tooling is disabled by default and none is exposed in this version.

## Reliability and rate limits

The REST API documents HTTP 429 for rate limiting; exact quotas are account/endpoint dependent rather than hard-coded here. The connector preserves `Retry-After`, applies timeout/cancellation with `AbortController`, and uses bounded exponential backoff only for retry-safe GET requests on 429/network/5xx failures. POST mutations are never blindly retried.

List tools enforce documented pagination maxima (generally 100). Provider validation/authentication/permission errors are not retried. Inngest function-level rate limiting and throttling are separate workflow features and should not be confused with REST API request limits.

## Security

- Credentials never cross the MCP tool boundary.
- Cloud REST and MCP origins are fixed and validated to prevent configuration-driven SSRF.
- Upstream MCP tools are allowlisted and their live schemas are checked before invocation.
- Provider output is returned with `untrustedProviderData: true`; event payloads, function output, traces and errors are data, never instructions.
- No signing keys, event keys, secrets-management or arbitrary request tools are exposed.
- Inputs are size-bounded; identifiers and pagination are validated locally.
- High-impact mutations require approval before any upstream request.
- Reruns are never automatically retried by the connector.

## Install and run

Requires Node.js 20+.

```bash
cd MCP-API/inngest
npm install
npm run build
npm test
npm start
```

The local connector speaks MCP over stdio, suitable for MCP hosts that can launch stdio servers. Example:

```json
{
  "command": "node",
  "args": ["/absolute/path/MCP-API/inngest/dist/src/index.js"],
  "env": { "INNGEST_API_KEY": "<secret-from-host>" }
}
```

## Error handling

REST errors are mapped to status/code/message internally without returning authorization headers. Missing credentials, validation failures, approval failures, 401/403 responses and mutation failures are not retried. If an upstream MCP call fails, the connector falls back to the equivalent documented REST operation rather than guessing a changed MCP schema.

## Testing

`npm test` uses fakes and requires no live credentials. Tests cover tool registration, pagination validation, official-MCP preference, MCP-to-REST fallback, approval denial, event sending, run cancellation and local identifier rejection.

## Limitations

- Cloud only: this wrapper does not proxy the unauthenticated local Dev Server MCP; clients can use that official endpoint directly for local workflows.
- The connector intentionally exposes a subset of Inngest Cloud MCP/API capabilities, prioritizing diagnostics plus tightly gated execution controls.
- The REST API v2 is stable but documented by Inngest as still in development; live MCP schemas and the official OpenAPI document should be treated as the compatibility source of truth.
- Environment selection is governed by the scope of `INNGEST_API_KEY`; this connector does not expose a tool that can escalate or switch credential scope.
