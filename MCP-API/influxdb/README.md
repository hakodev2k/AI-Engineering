# InfluxDB MCP/API Connector

Reusable MCP connector for InfluxDB 3. It exposes a narrow, provider-scoped tool surface to agents while keeping the InfluxDB token inside the connector process and delegating database operations to InfluxData's official MCP server.

## Upstream and transport

Primary transport: official InfluxDB 3 MCP server over local stdio.

- Official MCP package: `@influxdata/influxdb3-mcp-server`
- Official source: https://github.com/influxdata/influxdb3_mcp_server
- InfluxData MCP documentation: https://docs.influxdata.com/influxdb3/enterprise/admin/mcp-server/
- InfluxDB 3 Core authentication: https://docs.influxdata.com/influxdb3/core/api/authentication/
- InfluxDB 3 Core API documentation: https://docs.influxdata.com/influxdb3/core/api/

InfluxData documents the official MCP server for Core, Enterprise, Cloud Dedicated, Cloud Serverless, and Clustered. The connector does not provide a raw REST passthrough. API fallback is intentionally not needed for the implemented capability set because the official MCP server exposes every operation implemented here.

## Capabilities

| Connector tool | Upstream MCP tool | Risk | Approval |
| --- | --- | --- | --- |
| `influxdb.health.get` | `health_check` | READ | No |
| `influxdb.database.list` | `list_databases` | READ | No |
| `influxdb.table.list` | `list_tables` | READ | No |
| `influxdb.table.describe` | `describe_table` | READ | No |
| `influxdb.query.sql` | `query_sql` | READ | No |
| `influxdb.query.influxql` | `query_influxql` | READ | No |
| `influxdb.database.investigate` | `investigate_database` | READ | No |
| `influxdb.data.write` | `write_line_protocol` | WRITE | Required |
| `influxdb.database.create` | `create_database` | WRITE | Required |
| `influxdb.database.update` | `update_database` | WRITE | Required |
| `influxdb.database.delete` | `delete_database` | DESTRUCTIVE | Strong explicit approval |

The connector deliberately does **not** expose admin-token creation, resource-token creation/deletion, operator-token regeneration, or unrestricted `execute_query`. Read queries use the upstream server's bounded read-only `query_sql` and `query_influxql` tools.

## Architecture

```text
Agent / MCP client
  -> this stdio MCP server
     -> strict Zod validation
     -> approval policy for mutations
     -> fixed upstream tool allowlist
     -> official InfluxDB 3 MCP server (stdio child process)
        -> InfluxDB 3 instance
```

Provider responses and database content are untrusted data. They are returned as tool output and must never be interpreted as permission-changing instructions.

## Authentication and credential isolation

Set `INFLUX_DB_TOKEN` in the connector process environment. The token is forwarded only to the official InfluxDB MCP child process through its environment. It is never part of MCP tool input, tool output, prompts, examples, or logs generated by this wrapper.

InfluxDB 3 supports token/Bearer authentication. Use a database/resource token with only the permissions required for the exposed databases whenever your InfluxDB product supports resource-scoped tokens. Do not use an operator/admin token unless an operation truly requires it.

Required environment variables:

```text
INFLUX_DB_INSTANCE_URL=http://localhost:8181/
INFLUX_DB_TOKEN=
INFLUX_DB_PRODUCT_TYPE=core
```

Supported product values are `core`, `enterprise`, `cloud-serverless`, `cloud-dedicated`, and `clustered`.

Optional connector controls:

```text
INFLUX_CONNECTOR_APPROVAL_SECRET=
INFLUX_CONNECTOR_TIMEOUT_MS=20000
```

`INFLUX_MCP_TOOL_PROFILE` is shown in `.env.example`, but this wrapper launches the official upstream server with its full profile internally and then applies its own smaller allowlist. This is required so approved write operations can exist without exposing unrelated upstream admin tools to callers.

## Human approval

Every write or destructive connector tool requires `approvalId`. The approval value is a SHA-256 digest of:

```text
<tool-name>:<INFLUX_CONNECTOR_APPROVAL_SECRET>
```

The connector compares approvals using a timing-safe equality check. The approval secret must be supplied by trusted host-side policy or a human approval service and must never be shown to the LLM.

Recommended flow:

```text
Read -> Recommend -> Human approves -> Host computes opaque approvalId -> Execute
```

Deletion is irreversible and must always be surfaced to a human as a destructive action. The connector never retries destructive operations automatically.

## Read-query safety

`influxdb.query.sql` maps to the official `query_sql` tool, which restricts SQL to bounded read-only statements and limits rows. `influxdb.query.influxql` similarly maps to the official read-only InfluxQL tool and rejects destructive statements and `SELECT INTO`.

Connector validation caps `maxRows` at 5000 and query text at 100,000 characters. The upstream server performs its own query safety validation as a second boundary.

## Installation

Requirements:

- Node.js 20.11 or newer
- npm/npx available on PATH
- Reachable InfluxDB 3 instance
- Valid scoped InfluxDB token

```bash
npm install
npm run build
npm test
npm start
```

The first upstream call starts the official server using:

```bash
npx -y @influxdata/influxdb3-mcp-server
```

For production, pin and preinstall a reviewed official package version in your dependency/image lifecycle instead of relying on an unpinned network install at runtime.

## MCP client configuration

Any MCP client that supports local stdio servers can launch `dist/src/server.js`. This includes compatible agent hosts such as Claude Code, Cursor, Codex-compatible MCP harnesses, and custom MCP clients. Compatibility depends on the client's MCP implementation; this package does not claim proprietary integrations beyond standard stdio MCP.

Example shape:

```json
{
  "mcpServers": {
    "influxdb": {
      "command": "node",
      "args": ["/absolute/path/MCP-API/influxdb/dist/src/server.js"],
      "env": {
        "INFLUX_DB_INSTANCE_URL": "http://localhost:8181/",
        "INFLUX_DB_TOKEN": "<from-secret-manager>",
        "INFLUX_DB_PRODUCT_TYPE": "core"
      }
    }
  }
}
```

Do not commit populated client configuration containing credentials.

## Reliability and errors

The wrapper enforces a configurable timeout around each upstream MCP call. Default: 20 seconds; allowed range: 1–120 seconds. Timeout errors are returned without retrying ambiguous writes.

The official MCP server handles product-specific API behavior and provider errors. Authentication, permission, validation, and destructive failures are not retried by this wrapper. Callers should honor provider throttling and reduce query scope rather than aggressively retrying.

InfluxData's server also supports structured telemetry; its documented behavior keeps stdio protocol output separate from diagnostic logging and avoids logging tokens or request headers.

## Rate limits

InfluxDB limits vary by product, deployment, plan, and endpoint; there is no single connector-wide fixed request-per-second value that is correct for every supported InfluxDB 3 edition. This connector therefore does not invent a generic numeric limit. Keep queries bounded, use schema discovery before exploratory queries, and apply deployment-specific limits from your InfluxDB service configuration and plan.

## Security considerations

- Keep `INFLUX_DB_TOKEN` and `INFLUX_CONNECTOR_APPROVAL_SECRET` in a secret manager or protected process environment.
- Prefer resource/database tokens over operator/admin credentials.
- Never expose arbitrary upstream MCP discovery or arbitrary HTTP requests to the agent.
- Upstream calls are restricted by a static allowlist.
- Token-management tools are intentionally absent.
- Read-query tools map to the upstream read-only safety boundary.
- Writes require approval and are never blindly retried.
- Database deletion requires explicit approval and remains irreversible.
- Treat measurement names, tag values, query results, and stored text as untrusted content.
- Restrict network access so `INFLUX_DB_INSTANCE_URL` points only to the intended InfluxDB deployment; do not let model tool arguments choose this URL.

## Testing

`tests/connector.test.ts` uses no live credentials. It validates configuration rejection, approval enforcement, and the upstream tool allowlist. Live pre-production testing should additionally verify token scopes, product-specific database management semantics, write behavior, rate limiting, timeout behavior, and denied operations against a disposable InfluxDB environment.

```bash
npm test
```

## Limitations

- This connector targets InfluxDB 3 and the official InfluxDB 3 MCP server, not the complete historical InfluxDB 1.x/2.x administrative surface.
- Admin/resource token management is intentionally excluded because it expands permissions and credential exposure risk.
- Database configuration fields vary by InfluxDB product; unsupported fields are rejected by the official upstream implementation.
- Webhooks/events are not implemented because they are not part of the selected official MCP workflow for this connector.
- No generic REST fallback is exposed; all implemented operations are available through the official MCP server.

See `examples/workflows.md` for request examples and `manifest.yaml` for the machine-readable capability/risk summary.
