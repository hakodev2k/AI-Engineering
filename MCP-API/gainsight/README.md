# Gainsight MCP/API Connector

Reusable MCP stdio connector for Gainsight CS customer-data workflows.

## Upstream strategy
Gainsight officially offers MCP across its platform. As of September 2026, Gainsight states that CS and Staircase MCP servers are live and Skilljar, Customer Communities, and PX MCP servers are beta. The public product material confirms governed read/write workflows but does not publish a stable reusable CS MCP endpoint and machine-readable tool contract suitable for this package. This connector therefore uses Gainsight's documented REST APIs for the selected Company and Relationship operations and does not depend on an unofficial MCP server.

Official sources researched: Gainsight MCP (`https://www.gainsight.com/mcp/`); API overview (`https://support.gainsight.com/gainsight_nxt/API_and_Developer_Docs/About/API_Documentation_Overview`); REST API key/M2M OAuth (`https://support.gainsight.com/gainsight_nxt/API_and_Developer_Docs/Generate_REST_API/Generate_REST_API_Key`); Company API (`https://support.gainsight.com/gainsight_nxt/API_and_Developer_Docs/Company_and_Relationship_API/Company_API_Documentation`); Relationship API (`https://support.gainsight.com/gainsight_nxt/API_and_Developer_Docs/Company_and_Relationship_API/Relationship_APIs`); Data Management API (`https://support.gainsight.com/gainsight_nxt/02Data_Management/Data_Management_API_Documentation/Data_Management_APIs`).

## Tools
`gainsight.company.describe`, `gainsight.company.query`, `gainsight.company.create`, `gainsight.company.update`, `gainsight.relationship.query`, `gainsight.relationship.create`, `gainsight.relationship.update`, and `gainsight.relationship.upsert`.

READ tools need no approval. WRITE tools require `GAINSIGHT_ALLOW_WRITES=true` and a payload-bound HMAC approval generated by a trusted host using `GAINSIGHT_APPROVAL_SECRET`. No delete, arbitrary HTTP, permission, billing, or security-administration tool is exposed.

## Authentication
Set `GAINSIGHT_BASE_URL` to the tenant's configured Gainsight API HTTPS origin and `GAINSIGHT_ACCESS_KEY` to the admin-generated API access key. The key is added only as the `accesskey` HTTP header inside the client and never appears in tool inputs or outputs. Gainsight also documents M2M OAuth; this package uses the access-key mechanism because it is directly documented for Company/Relationship APIs. Access keys do not expire automatically, so store and rotate them carefully. For deployments that require expiring credentials, adapt the credential provider to Gainsight M2M OAuth without changing tool contracts.

## Install and run
Requires Node.js 20+.
```bash
npm install
npm run build
npm test
npm start
```
Configure any MCP client capable of launching a stdio server to run `node dist/src/server.js`, with secrets injected by the host/secret manager.

## Architecture and security
`MCP client -> strict schemas -> permission/approval policy -> credential-isolated Gainsight client -> tenant REST API`. The base URL is configuration-only, must be an HTTPS origin, and callers cannot provide arbitrary URLs. Identifiers, page sizes, key counts, record counts, and scalar record values are bounded. Provider content is marked untrusted and must never be interpreted as instructions, authorization, or permission changes. Do not log credentials or unnecessary customer data.

## Reliability and rate limits
Requests have AbortController timeouts. Retries are bounded with exponential backoff and `Retry-After` support. Only explicitly retry-safe reads are replayed; writes are single-attempt to avoid duplicate mutations. Authentication, validation, permission, and ordinary 4xx failures are not retried. Company/Relationship reads expose explicit limit/offset rather than silently draining datasets.

Gainsight documents recommended synchronous limits of 100 calls/minute and up to 100,000/day for many APIs, with some object APIs documenting 50,000/day; exact limits can vary by package. Bulk/asynchronous guidance is typically 10/hour and 100/day. This connector performs no bulk fan-out and surfaces available throttling metadata.

## Permissions and approval
Gainsight's access key is broad tenant authentication. Provider-side authorization remains authoritative. Keep writes disabled by default and use a dedicated integration identity/configuration where available. The model cannot enable writes or derive the approval secret. A human/trusted orchestrator should review the exact mutation, compute the approval fingerprint, and then execute it.

## Testing
`npm test` uses mocked fetch and no live credentials. Tests cover auth/base URL validation, unique tool registration, credential isolation, payload-bound write approval, throttling retry, and non-retry of writes.

## Events and webhooks
Gainsight exposes event APIs and product-specific event mechanisms, but they use different credentials/contracts and are intentionally outside this connector's focused surface. No webhook receiver or arbitrary event publisher is exposed.

## Limitations
This is a focused CS data connector, not a mirror of the entire Gainsight platform. It does not proxy the official MCP service because a stable public endpoint/tool schema was not identified in the official public materials reviewed. It omits CTA, Timeline, Success Plans, PX, Community, Skilljar, event publishing, bulk jobs, deletes, user administration, and arbitrary custom-object mutation. Tenant schemas differ, so callers should use `company.describe` before relying on custom fields. See `examples/workflows.md` for safe workflows.
