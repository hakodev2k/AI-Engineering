# Keygen MCP/API Connector

Reusable MCP server exposing a focused subset of the Keygen software-licensing API for AI agents and MCP clients.

## Provider and transport

Provider: Keygen.

Upstream transport: official Keygen REST API at `https://api.keygen.sh/v1/accounts/{account}`. Keygen's official documentation currently presents an HTTP/JSON API and an official Go SDK; no official Keygen MCP server is used by this connector. The connector therefore exposes Keygen capabilities as local MCP tools over stdio while keeping the upstream transport REST-only.

Official references:

- API reference: https://keygen.sh/docs/api/
- Authentication: https://keygen.sh/docs/api/authentication/
- Rate limiting: https://keygen.sh/docs/api/rate-limiting/
- Licenses: https://keygen.sh/docs/api/licenses/
- Machines: https://keygen.sh/docs/api/machines/
- Webhooks: https://keygen.sh/docs/api/webhooks/

## Implemented capabilities

| MCP tool | Upstream | Risk | Approval |
|---|---|---|---|
| `keygen.license.list` | `GET /licenses` | READ | No |
| `keygen.license.get` | `GET /licenses/{id}` | READ | No |
| `keygen.license.validate` | `POST /licenses/{id}/actions/validate` | READ | No |
| `keygen.license.create` | `POST /licenses` | WRITE | Required |
| `keygen.license.suspend` | `POST /licenses/{id}/actions/suspend` | HIGH_RISK | Required |
| `keygen.license.reinstate` | `POST /licenses/{id}/actions/reinstate` | HIGH_RISK | Required |
| `keygen.machine.list` | `GET /machines` | READ | No |
| `keygen.machine.deactivate` | `DELETE /machines/{id}` | DESTRUCTIVE | Required and disabled by default |

The connector deliberately does not expose arbitrary raw HTTP requests, token management, account permissions, product/policy deletion, release publishing, billing-like operations, or unrestricted webhook administration.

## Architecture

```text
MCP client
  -> stdio MCP server (`src/server.ts`)
  -> schema validation + risk policy
  -> KeygenClient (`src/client.ts`)
  -> credential isolation (`src/config.ts`)
  -> Keygen REST API
```

Provider responses are treated as untrusted data. They are serialized as tool output and never interpreted as instructions or used to change connector permissions.

## Authentication

Keygen supports API-token authentication through the `Authorization` header using `Bearer` or `Token`. This connector uses:

```text
Authorization: Bearer <KEYGEN_TOKEN>
```

Configure credentials only in the connector process environment. They are never accepted as MCP tool arguments and are never returned in tool output or error messages.

Required variables:

```text
KEYGEN_ACCOUNT=
KEYGEN_TOKEN=
```

Optional variables:

```text
KEYGEN_API_BASE_URL=https://api.keygen.sh
KEYGEN_TIMEOUT_MS=15000
KEYGEN_APPROVAL_SECRET=
KEYGEN_ALLOW_WRITES=false
KEYGEN_ALLOW_DESTRUCTIVE=false
```

`KEYGEN_ACCOUNT` may be the account ID or account slug supported by Keygen.

Use a Keygen token with only the permissions necessary for the tools you intend to enable. Read-only deployments should use a token that cannot create, suspend, reinstate, or deactivate resources.

## Installation

Requires Node.js 20+.

```bash
npm install
npm run build
```

Copy `.env.example` into the environment configuration used by your MCP host. Do not commit real credentials.

## Running

```bash
npm start
```

The server uses MCP stdio. Configure an MCP client to launch the built server process and provide the environment variables outside the model conversation.

## Permission and approval model

`READ` operations execute when the configured Keygen token permits them.

`WRITE` and `HIGH_RISK` operations require all of the following:

1. `KEYGEN_ALLOW_WRITES=true`.
2. `KEYGEN_APPROVAL_SECRET` stored in the MCP host environment.
3. An `approvalId` generated by the trusted host as `HMAC-SHA256(actionName, KEYGEN_APPROVAL_SECRET)`.

`DESTRUCTIVE` operations additionally require `KEYGEN_ALLOW_DESTRUCTIVE=true`.

The model must never be given `KEYGEN_APPROVAL_SECRET`. Approval tokens are action-scoped: a token generated for `keygen.license.create` cannot authorize `keygen.license.suspend` or `keygen.machine.deactivate`.

## Tool inputs

### `keygen.license.list`

- `limit`: 1–100, default 25.
- `page`: positive page number.
- `status`: one of `ACTIVE`, `INACTIVE`, `EXPIRING`, `EXPIRED`, `SUSPENDED`, `BANNED`.

### `keygen.license.get`

- `id`: license UUID.

### `keygen.license.validate`

- `id`: license UUID.
- `fingerprint`: optional machine fingerprint. The connector sends it through Keygen's validation scope as a one-element `fingerprints` array.

### `keygen.license.create`

- `policyId`: required policy UUID.
- `name`: optional license name.
- `expiry`: optional RFC 3339/ISO timestamp with offset.
- `approvalId`: required host approval token.

### `keygen.license.suspend` / `keygen.license.reinstate`

- `id`: license UUID.
- `approvalId`: required host approval token.

### `keygen.machine.list`

- `limit`: 1–100, default 25.
- `page`: positive page number.
- `license`: optional license UUID filter.

### `keygen.machine.deactivate`

- `id`: machine UUID.
- `approvalId`: required host approval token.

## Reliability

The client applies a per-request timeout, rejects redirects, validates the configured API origin, and bounds pagination inputs.

Only `GET` requests are retried. Retries are bounded to three attempts and are used only for HTTP `429` and `5xx` responses. Backoff is exponential and honors `Retry-After` when present. Mutating requests and validation POSTs are never automatically retried because their outcome may be unknown after a network failure.

Authentication, authorization and validation failures are not retried.

## Rate limits

Keygen documents rate limiting per token/IP combination. Client-side traffic has documented burst windows, while server-side limits vary by token/account usage. Keygen returns `429 Too Many Requests` when throttled and documents `X-RateLimit-*` plus `Retry-After` headers.

This connector honors `Retry-After` for retryable read requests and caps delays to avoid an unbounded MCP call. It does not hide throttling for writes; callers receive the provider error and can decide whether to retry after checking the real-world operation state.

## Error handling

Provider JSON:API errors are mapped to sanitized `KeygenError` messages using the documented error title/detail where available. Raw credentials are never included. Timeout and network errors are mapped separately.

A write timeout or network failure may leave outcome unknown. The connector intentionally does not retry such writes blindly.

## Security considerations

- Credentials stay in the connector environment and are not exposed as tool arguments.
- The default configuration is read-only.
- Destructive machine deactivation is disabled unless explicitly enabled.
- Tool schemas restrict UUIDs, page sizes, status values, expiry format and string lengths.
- Custom API origins require HTTPS except explicit loopback test URLs, reducing SSRF and credential-forwarding risk.
- Redirects are rejected so bearer credentials are not followed to another host.
- Retrieved license and machine metadata must be treated as untrusted external data.
- The connector does not dynamically discover or automatically trust tools.
- The connector does not expose a generic `request` or `execute` escape hatch.

## Webhooks

Keygen supports webhook endpoints and signed webhook events, but webhook management is intentionally not implemented in this connector. This keeps the initial agent-facing surface focused on licensing operations and avoids silently adding external callback destinations. A future separate connector revision should verify Keygen webhook signatures and place endpoint creation/deletion behind explicit high-risk approval.

## Testing

Unit tests use mocked `fetch` implementations and synthetic credentials only.

```bash
npm test
```

Covered behavior includes configuration validation, default write denial, action-scoped approval, destructive-operation gating, bearer-token isolation, read requests and sanitized provider errors.

## Limitations

- No official upstream MCP transport is used; all implemented capabilities use Keygen's REST API.
- The connector does not create policies, users, entitlements, products, webhook endpoints, packages or releases.
- License creation requires an existing policy UUID.
- Only one machine fingerprint is accepted by the MCP validation tool, although Keygen's REST validation API supports arrays of fingerprints and additional scopes.
- OAuth is not implemented because these server-side tools use Keygen API-token authentication.
- Live integration tests are intentionally excluded from the default test suite.
