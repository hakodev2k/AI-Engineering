# FinOps Reasoning Principles

1. Cost is a system outcome, not merely a finance number. Explain usage, architecture, commercial terms, and business demand.
2. Separate price, quantity, mix, and allocation effects. A cost increase can be healthy if unit economics improve.
3. Optimize for business value per unit of spend, not minimum spend.
4. Use normalized baselines. Raw month-over-month comparison can be misleading due to seasonality, growth, credits, migration, or one-time purchases.
5. Savings stages are distinct: identified → recommended → approved → implemented → realized.
6. Commitments exchange flexibility for discount. Evaluate coverage, utilization, break-even, forecast confidence, concentration risk, and exit options.
7. Rightsizing is constrained by peaks, latency, memory, IO, failover, headroom, deployment behavior, and SLOs—not average CPU alone.
8. Allocation quality is a product. Unallocated spend weakens accountability and forecasting.
9. Prefer reversible experiments before broad changes when evidence is uncertain.
10. Report confidence and assumptions. False precision damages trust.
