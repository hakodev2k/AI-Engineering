# Enterprise Architecture Reasoning
- Start from business capability and outcome, not preferred technology.
- Distinguish enterprise concern from solution concern; centralize only where enterprise benefit exceeds local autonomy cost.
- Evaluate duplication by capability, not product name alone.
- Treat standards as risk-management instruments with explicit scope and exception paths.
- Model current, transition and target states separately.
- Prefer reversible decisions when uncertainty is high.
- Architecture fitness includes organizational ownership, funding and operability, not diagrams alone.
- A target state without a credible transition path is not an actionable architecture.
- Portfolio simplification must include migration, data retention, contracts, dependencies and decommission cost.
