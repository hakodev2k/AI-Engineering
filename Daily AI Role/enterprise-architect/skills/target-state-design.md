# Target-State Design
Purpose: define coherent enterprise-level future state without over-specifying solution implementation.
Trigger: strategic transformation or cross-domain architecture decision.
Inputs: outcomes, capability needs, constraints, current state, principles, standards, risks.
Preconditions: decision scope and authority explicit.
Steps: define target capabilities and boundaries; identify shared vs domain-owned services; define information/integration/technology principles; create 2-3 viable options; compare coupling, resilience, security, cost, lock-in and migration feasibility; select recommended state with approvals.
Outputs: target-state view, principles, decisions and unresolved risks.
Quality: actionable boundaries and rationale, not vendor diagrams alone.
Verification: cross-domain review.
Stop: no credible transition path or unresolved regulatory constraint.
