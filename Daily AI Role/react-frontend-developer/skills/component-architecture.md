# Skill: Component Architecture
Purpose: define maintainable React boundaries and ownership. Trigger: new feature, large component, reusable behavior or repeated coupling. Inputs: user flow, design, current tree, state ownership. Preconditions: behavior and constraints known. Context/tools: repository search, component graph, design system. Steps: map user behavior; identify stable domain/UI boundaries; choose state owner; separate integration from presentation when useful; reuse existing primitives; define props/events; check shared impact. Decisions: local vs shared component, composition vs configuration, controlled vs uncontrolled. Constraints: avoid speculative abstractions. Output: component/data-flow plan. Quality: cohesive ownership, minimal cross-boundary knowledge. Verification: trace every required state and event. Failure: escalate conflicting design-system ownership. Stop: each user behavior has one clear owner.
