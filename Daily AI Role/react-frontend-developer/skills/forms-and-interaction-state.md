# Skill: Forms and Interaction State
Purpose: implement predictable forms and complex interaction flows. Trigger: editable data, multi-step input or async submission. Inputs: fields, validation rules, persistence behavior. Preconditions: server/client validation responsibility known. Steps: define canonical form state; separate touched/dirty/submitting/server errors; validate at useful time; prevent duplicate submission; restore focus to first actionable error; preserve unsaved data intentionally; map server errors to fields/global state. Decisions: controlled/local library/native form. Constraints: do not duplicate business validation as an independent policy source. Output: interaction state model and implementation. Quality: no unreachable or contradictory state. Verification: keyboard, repeated submits, server rejection, navigation away. Stop: every state transition has an exit path.
