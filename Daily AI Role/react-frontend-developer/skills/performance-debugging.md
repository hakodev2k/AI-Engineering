# Skill: Performance Debugging
Purpose: diagnose browser performance regressions with evidence. Trigger: slow interaction, poor web-vital/telemetry, render storm or bundle growth. Inputs: trace, route, device/network profile, recent changes. Preconditions: reproducible scenario or production evidence. Steps: establish baseline; profile network/main thread/render; identify dominant bottleneck; form bounded hypotheses; change one dominant factor; remeasure; check correctness/a11y impact. Decisions: fetch strategy, virtualization, splitting, memoization, algorithm/data shape. Constraints: max two speculative fixes without confirming signal. Output: before/after evidence and residual risk. Quality: improvement on relevant user scenario. Failure: escalate when backend/network dominates. Stop: target met or bottleneck assigned with evidence.
