# Skill: Accessibility Implementation
Purpose: make critical tasks operable by keyboard and assistive technology. Trigger: new/changed interactive UI. Inputs: interaction design, semantic structure, content. Preconditions: intended behavior known. Steps: choose native semantic element; verify accessible name; keyboard order/activation; visible focus; error association; status announcement; modal focus trap/return; contrast and non-color cues; zoom/responsive behavior. Decisions: native semantics vs ARIA only when native cannot represent behavior. Constraints: ARIA must not override correct native semantics. Output: a11y findings and implementation. Quality: critical path usable without pointer. Verification: keyboard pass plus accessibility tooling where available. Failure: high-severity task blocker prevents completion. Stop: no unresolved critical accessibility issue.
