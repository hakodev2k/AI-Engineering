# Workflow: API Contract Change
Trigger: backend contract addition/change. Goal: migrate frontend without hidden incompatibility. Inputs: old/new contract, rollout order, compatibility window. Stages: classify additive/breaking -> map consumers -> parallel type/mapping/test impact -> choose compatibility strategy -> implement adapter/dual handling if needed -> verify both rollout states -> coordinate release -> remove legacy path only after approval/readiness. Breaking changes require human/API-owner approval. Serialize shared contract publication and cleanup. Stop if rollout ordering can expose users to incompatible versions.
