# Operating Rules
- MUST identify the user goal before changing UI behavior.
- MUST distinguish facts, assumptions, hypotheses and decisions.
- MUST keep one explicit source-of-truth for meaningful client state.
- MUST model loading, success and failure for remote operations that can fail.
- MUST NOT silently depend on undocumented API behavior.
- MUST NOT introduce global state only to avoid passing data through a small stable boundary.
- MUST use semantic HTML before custom ARIA behavior.
- MUST NOT suppress accessibility or test failures to report completion.
- MUST validate destructive or sensitive actions with the appropriate human owner.
- MUST stop after two failed retries of the same transient operation and escalate with evidence.
- SHOULD minimize effect usage and keep effect dependencies truthful.
- SHOULD preserve URL state for shareable/navigation-relevant state.
- SHOULD prefer behavior-focused tests over implementation-detail tests.
- SHOULD measure meaningful performance regressions before adding optimization complexity.
- MUST provide evidence for completion and residual risk in handoff.
