# Workflow: Versioned Migration Release
**Trigger:** release includes schema/data/contract migration. **Goal:** preserve compatibility and recoverability. Prefer expand/contract: add compatible schema/contract -> deploy readers/writers that support both -> migrate/backfill with checkpoints -> verify -> switch behavior -> later remove old shape. Require dependency sequencing review, data owner approval for irreversible steps, clear point of no return, monitored backfill, and recovery plan. Parallelize non-mutating verification; serialize state transitions. Stop on corruption, incompatible clients, lag beyond threshold, or missing recovery evidence.
