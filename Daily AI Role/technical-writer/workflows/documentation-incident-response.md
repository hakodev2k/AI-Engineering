# Workflow: Documentation Incident Response

**Trigger:** documentation causes/extends incident, unsafe action, widespread confusion, or critical support failure.
**Goal:** reduce harm and prevent recurrence.
**Inputs:** incident evidence, affected pages, product state, user impact.
**Stages:** classify severity → contain misleading content (banner/unpublish/clarify through authorized channel) → gather evidence → parallel source/usage/terminology review → identify safest correction → human approval for security/legal/destructive guidance → publish correction → verify user path → record failure learning.
**Retries:** max 2 failed correction-validation attempts before broader reassessment/escalation.
**Outputs:** corrected content, incident record, prevention actions.
**Failure:** uncertain product state or widening impact → escalate immediately.
**DoD:** harmful ambiguity removed, correction verified, owners/due dates assigned.
