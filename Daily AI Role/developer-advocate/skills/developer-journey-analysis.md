# Skill: Developer Journey Analysis
**Trigger:** onboarding friction, low activation, repeated support questions, or launch preparation.
**Inputs:** target persona, desired job, docs/product flow, telemetry, issue/support evidence.
**Preconditions:** journey and environment are identifiable.
**Procedure:** map prerequisites → first action → auth/setup → core task → success signal → next action; reproduce the journey; record time, decisions, failure points, unclear concepts, unnecessary permissions, and dead ends; classify friction by severity/frequency; propose smallest high-leverage fixes.
**Decisions:** docs fix vs product fix vs SDK fix vs sample fix vs support-only explanation.
**Outputs:** journey map, evidence, friction backlog, prioritized recommendations.
**Quality:** another developer can reproduce findings.
**Verification:** repeat critical path after proposed fix.
**Stop:** unresolved product behavior, missing access, or security ambiguity requires escalation.
