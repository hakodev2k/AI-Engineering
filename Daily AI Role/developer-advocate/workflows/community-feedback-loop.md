# Workflow: Community Feedback Loop
**Trigger:** recurring or high-impact developer feedback.
**Goal:** convert signal into owned, evidence-backed improvement.
**Inputs:** issues, discussions, events, support themes, telemetry where available.
**Stages:** collect → sanitize → deduplicate → classify → reproduce representative cases → score impact/confidence → route to owner → track response → communicate verified outcome → record lesson.
**Parallel:** independent clusters may be analyzed concurrently.
**Synchronization:** Developer Advocate consolidates cross-channel duplicates.
**Retry:** one evidence-request cycle for incomplete reports; unresolved high-impact ambiguity escalates.
**DoD:** actionable feedback has owner/state, or documented reason it cannot proceed.
