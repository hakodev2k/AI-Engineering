# Workflow: Tutorial and Sample Production
**Trigger:** new or updated educational asset.
**Goal:** produce a reproducible developer task path.
**Inputs:** advocacy brief, contracts, supported environment.
**Stages:** define outcome → build minimal implementation → draft instructions → clean-run test → independent sample verification + fact review in parallel → corrections → final publish check → delivery.
**Dependencies:** technical contract before final wording; sample success before publish.
**Checkpoint:** expected output and failure guidance are reproducible.
**Retry:** 2 review/fix cycles then escalate.
**Failure path:** mark blocked; do not publish partial success as complete.
**DoD:** another developer completes the target outcome using only documented prerequisites.
