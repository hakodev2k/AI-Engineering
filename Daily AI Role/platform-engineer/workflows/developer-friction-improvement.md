# Workflow: Developer Friction Improvement

**Trigger:** repeated manual work, support load, slow task completion, onboarding failure, or low platform adoption.

**Goal:** reduce a measured developer burden without weakening safety or ownership.

**Stages:** gather evidence -> map journey -> identify root cause -> rank hotspots -> choose one high-leverage reversible experiment -> define metric -> implement/pilot -> compare evidence -> keep, revise, or revert -> capture lesson.

Use no more than two fix/retest cycles before re-framing the problem. Do not automate a broken process merely to preserve it.

**Done:** measured before/after evidence, user feedback, safety/reliability review, decision, owner, and next review.
