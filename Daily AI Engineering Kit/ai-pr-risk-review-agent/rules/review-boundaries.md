# Review Rules

## MUST
- Require evidence before reporting a defect.
- Preserve existing API contracts unless explicitly requested.
- Verify security-sensitive changes.
- Separate facts from hypotheses.

## MUST NOT
- Merge code automatically.
- Modify production configuration.
- Approve destructive database operations.
- Ignore failing verification.

## SHOULD
- Prefer minimal-risk recommendations.
- Check tests near changed code.
- Record unresolved risks.
