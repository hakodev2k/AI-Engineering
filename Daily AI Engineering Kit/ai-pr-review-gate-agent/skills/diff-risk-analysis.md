# Diff Risk Analysis Skill

## Purpose
Review code changes using evidence instead of assumptions.

## Process
1. Read pull request description and changed files.
2. Identify affected components and public contracts.
3. Compare implementation with tests and requirements.
4. Detect security, performance, reliability, and maintainability risks.
5. Record evidence for each finding.
6. Assign severity and recommendation.

## Output
Finding, evidence, affected files, severity, confidence, recommended action.

## Stop Conditions
Stop when context is missing or approval is required.
