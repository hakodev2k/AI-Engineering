# Maintainers

This document identifies current stewardship and the responsibilities attached to repository maintenance.

## Current maintainer

- [@hakodev2k](https://github.com/hakodev2k) — repository owner and default reviewer.

The repository [CODEOWNERS](.github/CODEOWNERS) file defines the review owner used by GitHub. This page explains responsibility; it does not grant access or override repository permissions.

## Responsibilities

Maintainers are expected to:

- preserve the pick-and-copy scope and collection boundaries;
- review content for clarity, standalone use, safety, evidence, and unnecessary duplication;
- protect private vulnerability reports and enforce the Code of Conduct;
- keep community documentation, issue forms, navigation, and audit tooling healthy;
- require additional subject-matter review for specialized or high-impact changes;
- disclose uncertainty and avoid presenting structural audit results as production certification.

## Decision and review model

Routine decisions follow [GOVERNANCE.md](GOVERNANCE.md). Security-sensitive, permission-expanding, externally visible, destructive, or taxonomy-wide changes require heightened review. The author of a high-impact change should not be its only substantive reviewer when an independent reviewer is available.

## Contact

- Use GitHub Issues for reproducible content, documentation, and tooling problems.
- Use the content proposal form for a new reusable asset.
- Follow [SUPPORT.md](SUPPORT.md) for usage questions.
- Follow [SECURITY.md](SECURITY.md) for private vulnerability reporting.

Do not send credentials, private prompts, customer data, internal logs, or vulnerability details through public issues.

## Continuity

If stewardship changes, update this file, `CODEOWNERS`, repository permissions, security-advisory access, and public support paths together. Open reviews and private security reports must have an explicit handoff owner before access is removed.
