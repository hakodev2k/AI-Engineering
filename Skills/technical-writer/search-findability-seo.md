# Documentation Search and Findability

## Purpose
Improve the probability that users discover the correct documentation through site search, web search, navigation, and cross-links.
## When to use
Use when users report “docs exist but I cannot find them,” search exits are high, or terminology varies.
## Inputs
Search queries, analytics, task map, terminology, metadata, platform search behavior.
## Context to inspect
Titles, headings, descriptions, aliases, URLs, canonical tags, duplicate pages, internal links.
## Core knowledge
Technical SEO starts with matching real user intent and canonical accurate content. Optimize findability without keyword stuffing or duplicate landing pages.
## Procedure
1. Gather real search vocabulary and failed queries.
2. Map intents to canonical pages.
3. Write descriptive unique titles and opening summaries.
4. Include common aliases while preserving canonical terminology.
5. Improve heading structure and contextual internal links.
6. Consolidate duplicate competing pages.
7. Maintain redirects and canonical/version metadata.
8. Ensure critical content is indexable by intended search systems.
9. Measure query success and refine.
## Decision points
Create a new page only when intent/content is genuinely distinct; otherwise strengthen the canonical page.
## Common failure patterns
Keyword stuffing, duplicate pages per synonym, obsolete versions outranking current docs, and navigation labels users do not recognize.
## Verification
Representative queries lead to the correct current page with fewer reformulations/dead ends.
## Expected output
More discoverable canonical documentation.
## Stop conditions
Escalate search-platform indexing defects authors cannot control.
