# How-to Guides

## Purpose
Help competent users accomplish a specific real-world task efficiently and safely.
## When to use
Use for configuration, integration, deployment, migration, troubleshooting, and operational tasks.
## Inputs
User goal, prerequisites, supported variants, risks, tested procedure.
## Context to inspect
Product behavior, existing conventions, permissions, side effects, rollback, common errors.
## Core knowledge
How-to content is goal-oriented. Keep conceptual explanation subordinate to the task and make consequential choices explicit.
## Procedure
1. Define one concrete outcome.
2. State prerequisites, permissions, and assumptions.
3. Identify destructive or irreversible steps.
4. Provide the shortest reliable sequence.
5. Explain decision branches where users must choose.
6. Add expected results after meaningful steps.
7. Cover common failure/recovery paths.
8. Include final verification and rollback/cleanup where relevant.
9. Test the procedure end to end.
## Decision points
Split guides when variants diverge substantially; keep small platform differences inline when comparison remains easy.
## Common failure patterns
Mixing multiple goals, unexplained prerequisites, unsafe commands, no rollback, and procedures never executed by the author/reviewer.
## Verification
Execute exactly as written in a representative environment and confirm expected outcome.
## Expected output
A concise, safe, verified task guide.
## Stop conditions
Do not publish destructive steps without validated safeguards and required approval context.
