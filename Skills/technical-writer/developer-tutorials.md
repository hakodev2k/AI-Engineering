# Developer Tutorials

## Purpose
Teach a successful first end-to-end experience while building a useful mental model.
## When to use
Use for onboarding to APIs, SDKs, frameworks, CLIs, or platforms.
## Inputs
Target outcome, prerequisites, supported environment, sample project, product behavior.
## Context to inspect
Installation, credentials, common setup failures, platform differences, current examples.
## Core knowledge
A tutorial is a guided learning path, not exhaustive reference. Minimize choices early and explain only concepts needed for the next action.
## Procedure
1. Choose one meaningful achievable outcome.
2. State prerequisites and expected duration.
3. Start from a reproducible clean environment.
4. Sequence small steps with observable checkpoints.
5. Use copyable but explainable examples.
6. Explain why key steps matter.
7. Add troubleshooting for likely blockers.
8. End with verification, cleanup, and next learning paths.
9. Test from scratch on supported environments.
## Decision points
Provide variants only after the primary path works; split advanced alternatives into separate guides.
## Common failure patterns
Too many choices, hidden setup, unexplained code dumps, stale screenshots, and no success checkpoint.
## Verification
A target user can complete the tutorial from a clean state using only documented prerequisites.
## Expected output
A reproducible learning journey with a verified result.
## Stop conditions
Stop publication when required setup or product behavior cannot be reproduced.
