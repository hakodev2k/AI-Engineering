# User Enablement and Workflow Guidance

## Purpose
Equip users to apply AI effectively within real workflows, including when to use it, how to review outputs, and how to recover from failure.

## When to use
Use before pilot onboarding, phased rollout, or when adoption is low despite technical availability.

## Inputs
Target workflows, user segments, model capabilities, known failure modes, policy boundaries, support channels, and training constraints.

## Context to inspect
Inspect existing job aids, onboarding, workflow documentation, user skill levels, recurring support issues, and places where AI changes decision-making responsibility.

## Core knowledge
Enablement should teach task judgment, not model trivia. Users need concrete examples, boundary conditions, verification habits, and escalation routes. The best guidance is embedded near the work rather than isolated in a one-time training session.

## Procedure
1. Segment users by role, task, and AI familiarity.
2. Define the specific behaviors required for safe, effective use.
3. Identify common misconceptions and high-risk misuse patterns.
4. Build workflow-based examples using realistic inputs and outputs.
5. Teach verification and correction steps for consequential tasks.
6. Explain prohibited or unsupported use cases plainly.
7. Provide escalation and support paths.
8. Embed concise guidance in the product or workflow where possible.
9. Observe early users and capture friction.
10. Revise materials using measured errors and support data.

## Decision points
Use live training for complex or high-risk workflows; use embedded guidance and short job aids for routine tasks. Do not overload users with implementation details that do not improve decisions.

## Common failure patterns
Generic prompt training, one-time launch workshops, hiding limitations, assuming all users have equal skill, and measuring attendance instead of behavior change.

## Verification
Observe representative users completing target tasks and confirm they know when to use AI, how to validate output, and when to escalate.

## Expected output
Role-specific enablement materials, embedded guidance, verification practices, support paths, and an improvement loop.

## Stop conditions
Stop when required user behavior conflicts with policy, or when the workflow is too unsafe for users to validate with available context.
