# Program Charter and Outcomes

## Purpose
Define a technical program with explicit business outcomes, technical goals, scope boundaries, success metrics, decision rights, and operating constraints.

## When to use
Use when initiating a cross-team technical initiative or rescuing a program whose goals have become ambiguous. Do not use as a substitute for detailed project plans.

## Inputs
Business objective, technical context, stakeholders, constraints, known dependencies, risks, budget/timeline assumptions.

## Context to inspect
Existing roadmaps, architecture decisions, product commitments, delivery calendars, ownership boundaries, incident history, regulatory requirements, and prior related initiatives.

## Core knowledge
A Senior Technical Program Manager converts strategy into an executable program system. The charter must separate outcomes from outputs, distinguish committed scope from discovery, and expose assumptions that can invalidate the plan.

## Procedure
1. Restate the business problem and desired measurable outcome.
2. Identify the technical capabilities required to achieve it.
3. Define in-scope and explicitly out-of-scope work.
4. Identify participating teams and accountable owners.
5. Define success metrics, leading indicators, and exit criteria.
6. Record constraints, assumptions, major dependencies, and unresolved questions.
7. Define governance cadence and decision rights.
8. Validate the charter with engineering, product, operations, and executive sponsors.
9. Freeze a versioned baseline and record approved changes thereafter.

## Decision points
Prefer outcome metrics over activity metrics. Split the program when substreams have materially different goals, owners, or risk profiles.

## Common failure patterns
Vague goals, hidden scope, treating dates as strategy, no accountable owner, output-only metrics, and unrecorded assumptions.

## Verification
Confirm every workstream maps to a named outcome, all key stakeholders accept the scope boundary, and metrics can be measured objectively.

## Expected output
An approved program charter that can drive planning, prioritization, escalation, and change control.

## Stop conditions
Stop and escalate when the sponsor cannot define success, ownership is unresolved, or mandatory scope exceeds feasible constraints.
