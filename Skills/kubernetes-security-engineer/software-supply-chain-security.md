# Software Supply Chain Security

## Purpose
Protect Kubernetes deployments from compromised source, dependencies, build systems, registries, and deployment artifacts.

## When to use
Use when designing CI/CD, artifact trust, release controls, or investigating supply-chain exposure.

## Inputs
Source repositories, pipeline definitions, builders, dependencies, registries, SBOMs, attestations, signing keys, and deployment identities.

## Preconditions
Map artifact flow from source commit to running pod and identify each trust boundary.

## Context to inspect
Inspect branch protection, CI identity, runner isolation, dependency pinning, build provenance, artifact immutability, signing, admission verification, and deployment permissions.

## Core knowledge
Supply-chain integrity requires verifiable linkage between reviewed source, controlled build, immutable artifact, and authorized deployment. Each mutable or privileged intermediary expands attack surface.

## Procedure
1. Map source-to-runtime lineage.
2. Harden repository and CI identities.
3. Isolate builders and minimize persistent credentials.
4. Pin and verify dependencies where practical.
5. Produce SBOM and provenance attestations.
6. Store immutable artifacts by digest.
7. Sign/attest releases with protected keys or keyless identity.
8. Verify provenance at deployment/admission.
9. Test revocation and compromised-artifact response.

## Decision points
Prefer identity-bound/keyless signing when organizational trust supports it; otherwise protect signing keys with strong custody. Choose policy strictness based on deployment criticality and ecosystem maturity.

## Common failure patterns
Signing after an untrusted build; mutable tags; privileged shared runners; deployment tokens in CI variables; provenance generated by the artifact producer without trustworthy isolation.

## Verification
Trace a deployed digest back to source and builder evidence; confirm unsigned/untrusted artifacts are rejected.

## Expected output
A verifiable source-to-runtime chain with enforceable trust policy.

## Stop conditions
Escalate on compromised signing/build identities or inability to establish artifact provenance.
