# Schedule and Critical Path Management

## Purpose
Build and actively manage a realistic schedule that exposes sequencing constraints, float, milestone risk, and the work that actually controls completion.

## When to use
Use for projects with meaningful dependencies, fixed dates, external lead times, or multiple workstreams.

## Inputs
Work packages, durations or ranges, dependencies, calendars, milestones, resource constraints, and external commitments.

## Context to inspect
Inspect hard versus soft dates, dependency types, approval lead times, release windows, resource calendars, and assumptions embedded in estimates.

## Core knowledge
Critical-path reasoning focuses management attention on work whose delay moves the project end date. Resource constraints and uncertainty can make a mathematically valid schedule operationally impossible.

## Procedure
1. Sequence work using real predecessor relationships.
2. Distinguish mandatory dependencies from preferred sequencing.
3. Apply realistic calendars and lead times.
4. Calculate or identify critical and near-critical paths.
5. Review float and milestone sensitivity.
6. Check resource contention and handoff bottlenecks.
7. Challenge artificial date constraints and excessive task overlap.
8. Define schedule buffers where uncertainty warrants them.
9. Track actual progress and remaining duration, not percent-complete theater.
10. Reforecast when assumptions or critical work change.

## Decision points
Crash work only when added resources can genuinely shorten duration. Fast-track parallel work only when rework risk is acceptable. Protect critical milestones before optimizing non-critical utilization.

## Common failure patterns
Hard-coding target dates as task logic, ignoring resource contention, reporting green because many non-critical tasks finished, and retaining obsolete baselines after material change.

## Verification
Confirm dependency logic is complete, critical work has owners, milestone forecasts reflect current remaining effort, and schedule changes reconcile with scope and risk records.

## Expected output
A maintained schedule with critical-path visibility, milestone forecasts, float, constraints, and recovery options.

## Stop conditions
Escalate when contractual dates are infeasible, dependency owners cannot commit, or recovery requires unauthorized cost, scope, or risk changes.
