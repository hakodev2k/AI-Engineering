# Executive Technical Communication

## Purpose
Translate complex engineering conditions into concise executive-level choices about risk, investment, timing, and business impact without losing essential technical truth.

## When to use
Use for executive reviews, major incidents, funding requests, architecture investments, security risk, delivery changes, or decisions spanning multiple organizations.

## Inputs
Decision needed, business outcome, technical evidence, financial or customer impact, options, risks, forecast, and confidence level.

## Context to inspect
Inspect the audience's decision authority, prior commitments, competing business priorities, and which technical details materially affect the choice.

## Core knowledge
Executives generally need consequence, options, recommendation, confidence, and required action. Technical precision matters, but implementation detail should support rather than obscure the decision.

## Procedure
1. Define the executive decision or awareness required.
2. Lead with business or customer impact.
3. State the current condition using verified evidence.
4. Explain the technical constraint in plain language.
5. Present a small set of realistic options.
6. Quantify cost, timing, risk, and uncertainty where defensible.
7. Recommend an option and explain why.
8. State what happens if no action is taken.
9. Make the requested decision, owner, and deadline explicit.
10. Preserve a deeper technical appendix or source for follow-up.

## Decision points
Use concise written briefs for durable decisions; use live discussion when trade-offs are contested or time-critical. Include technical detail only when it changes the decision.

## Common failure patterns
Architecture lectures, hiding uncertainty, unsupported ROI, excessive acronyms, status without an ask, and presenting only one option when meaningful alternatives exist.

## Verification
Verify the audience can identify the impact, options, recommendation, key uncertainty, and action required without needing to decode implementation details.

## Expected output
A concise executive technical brief or update that enables a clear decision.

## Stop conditions
Escalate or restrict distribution when information is confidential, security-sensitive, legally privileged, or governed by disclosure policy.
