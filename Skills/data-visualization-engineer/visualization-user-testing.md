# Visualization User Testing

## Purpose
Validate that intended users can correctly interpret and operate a visualization to complete real analytical tasks.

## When to use
Before major dashboard releases, redesigns, or when usage data suggests confusion.

## Inputs
Prototype or product, target personas, analytical tasks, hypotheses, representative data.

## Core knowledge
Visual appeal does not prove comprehension. Testing should measure task success, interpretation accuracy, time, confidence, navigation errors, and misconceptions without coaching users toward the intended answer.

## Procedure
1. Define the decisions and interpretations to validate.
2. Recruit representative users or the closest available proxies.
3. Create realistic task scenarios with known expected answers.
4. Ask users to think aloud without teaching the interface.
5. Observe where they look, filter, hesitate, and misinterpret.
6. Probe understanding of units, baselines, uncertainty, and filter state.
7. Record task success, time, errors, and confidence.
8. Separate discoverability problems from data/semantic problems.
9. Prioritize fixes by decision risk and frequency.
10. Retest materially changed flows.

## Decision points
Use moderated testing for complex diagnostic workflows and unmoderated testing for larger samples of bounded tasks. Pair qualitative findings with telemetry when available.

## Common failure patterns
Testing only with authors; leading questions; asking preferences instead of tasks; unrealistic clean data; ignoring wrong-but-confident interpretations.

## Verification
Confirm revised designs improve the failed task metrics and no new interpretation errors appear.

## Expected output
Evidence-based usability findings, severity, root hypotheses, and validated design changes.

## Stop conditions
Stop conclusions when participant profiles do not reasonably represent the target audience or tasks cannot be evaluated with available data.
