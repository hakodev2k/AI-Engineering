# Technical Livestream Production

## Purpose
Produce live technical sessions that remain educational, accurate, accessible, and resilient to live-system failures.

## When to use
Use for coding streams, launch walkthroughs, office hours, interviews, and community broadcasts.

## Inputs
Audience, topic, run-of-show, code/demo, guests, platform constraints, moderation plan.

## Context to inspect
Technical claims, demo dependencies, guest expertise, latency, accessibility/captions, chat moderation, recording permissions, and incident contingencies.

## Core knowledge
Live formats reward interaction but increase operational and accuracy risk. A senior practitioner separates prepared claims from exploratory debugging and labels uncertainty clearly.

## Procedure
1. Define learning outcome and audience baseline.
2. Create a timed run-of-show with interaction windows.
3. Validate code, dependencies, accounts, and displayed data.
4. Prepare backup demo states and local artifacts.
5. Configure captions, readable terminal/editor, and audio checks.
6. Brief guests on scope, disclosures, and handoffs.
7. Assign chat moderation and escalation.
8. During delivery, distinguish verified facts from live hypotheses.
9. Capture unanswered questions for follow-up.
10. Review recording for corrections, links, chapters, and reusable assets.

## Decision points
Use live coding for reasoning/process; prepared demos for deterministic teaching. Defer questions requiring private data, security investigation, or unsupported speculation.

## Common failure patterns
Unmoderated chat, leaked secrets, unreadable code, aimless debugging, unsupported claims, no backup, and ignoring accessibility.

## Verification
Complete technical and AV preflight, secret scan visible surfaces, test fallback, and publish corrections when live statements prove inaccurate.

## Expected output
A reliable live session plus accurate follow-up resources and captured developer feedback.

## Stop conditions
Stop or switch to fallback if sensitive data appears, production systems are at risk, harassment cannot be moderated, or a demo failure no longer supports the learning objective.
