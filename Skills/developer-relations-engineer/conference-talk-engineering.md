# Conference Talk Engineering

## Purpose
Design technically credible conference talks that teach a coherent idea, demonstrate evidence, and respect audience time.

## When to use
Use for CFP submissions, key technical sessions, launch talks, or external conference presentations.

## Inputs
Audience, event theme, session length, technical thesis, evidence, demo constraints, venue rules.

## Context to inspect
Expected audience level, competing sessions, prior talks, product maturity, claim support, accessibility, recording policy, and network/AV constraints.

## Core knowledge
A strong technical talk has one defensible thesis, an audience transformation, narrative progression, concrete evidence, and controlled scope. A talk is not a feature catalog.

## Procedure
1. Define what the audience should understand or do afterward.
2. Write a one-sentence thesis and test its novelty/relevance.
3. Select only evidence needed to support it.
4. Build narrative: problem, constraints, approach, evidence, trade-offs, application.
5. Design demos with deterministic fallback artifacts.
6. Budget time for transitions and questions.
7. Remove jargon or explain it at first use.
8. Rehearse aloud under realistic timing.
9. Peer-review technical claims and accessibility.
10. Update volatile details immediately before delivery.

## Decision points
Prefer live demos only when their pedagogical value exceeds failure risk. Use code depth appropriate to audience, not speaker preference.

## Common failure patterns
Feature dumps, unsupported benchmarks, too many concepts, tiny code, network-dependent demos, rehearsing silently, and sales language at technical venues.

## Verification
Run timed rehearsals, validate all claims/sources, test demo fallback, and confirm the talk still works if live systems fail.

## Expected output
A focused talk narrative, validated technical material, resilient demo plan, and delivery-ready timing.

## Stop conditions
Stop when claims cannot be substantiated, disclosure/embargo rules are unresolved, or the session cannot fit without removing essential reasoning.
