# Open Source Community Engagement

## Purpose
Engage open-source communities respectfully and effectively while separating contribution from promotional extraction.

## When to use
Use when a product integrates with open-source projects, sponsors ecosystems, contributes upstream, or depends on community-maintained software.

## Inputs
Project governance, contribution guide, roadmap, issue tracker, integration needs, internal engineering capacity, legal policy.

## Context to inspect
Maintainer priorities, project norms, release cadence, licensing, security process, contributor expectations, and historical company interactions.

## Core knowledge
Open-source trust is earned through useful, maintainable contributions and respect for governance. Company urgency does not override maintainer priorities.

## Procedure
1. Read governance, contribution, security, and communication guidance.
2. Understand the project's goals before proposing changes.
3. Search existing issues/PRs and discuss large work before implementation.
4. Scope contributions to upstream value, not only vendor-specific promotion.
5. Follow style, testing, documentation, and review conventions.
6. Respond to maintainer feedback promptly and respectfully.
7. Plan long-term ownership for contributed code.
8. Disclose affiliation and conflicts where relevant.
9. Support maintainers through documentation, triage, sponsorship, or engineering work when appropriate.
10. Measure ecosystem outcomes without pressuring maintainers for marketing participation.

## Decision points
Contribute upstream when functionality is broadly useful; maintain an adapter externally when vendor-specific. Sponsor when maintainer capacity is the bottleneck, without buying governance influence.

## Common failure patterns
Drive-by PRs, bypassing maintainers, promotional issues, abandoning code after merge, entitlement from sponsorship, and ignoring license/security processes.

## Verification
Confirm contributions pass project checks, have maintenance ownership, follow governance, and are accepted on technical/community merit.

## Expected output
Sustainable upstream contributions and documented relationships that improve both developer integration and ecosystem health.

## Stop conditions
Stop when legal/licensing status is unclear, disclosure is prohibited, maintainers reject the direction, or contribution would impose unowned maintenance burden.
