# Developer Event Portfolio Planning

## Purpose
Select and operate an event portfolio based on developer relevance, technical outcomes, and sustainable team capacity.

## When to use
Use for quarterly/annual event planning, sponsorship decisions, community roadshows, and conference prioritization.

## Inputs
Audience strategy, event candidates, historical outcomes, budget, staff capacity, product milestones, geographic coverage.

## Context to inspect
Attendee composition, technical depth, format, organizer reputation, code of conduct, accessibility, competing events, lead time, and prior engagement quality.

## Core knowledge
Event value can include learning, adoption, ecosystem trust, research, contributor relationships, and launch reach. Sponsorship size is not a proxy for technical impact.

## Procedure
1. Define event objectives by developer segment.
2. Score candidates on audience fit, technical format, trust, timing, cost, and reusable value.
3. Estimate total cost including preparation and engineering time.
4. Choose participation mode: attend, speak, workshop, sponsor, booth, community meetup, or skip.
5. Define pre-event content/demo readiness.
6. Establish staffing roles and escalation paths.
7. Capture structured developer feedback during the event.
8. Follow up with resources and product feedback owners.
9. Measure outcomes against predeclared goals.
10. Feed results into future portfolio decisions.

## Decision points
Prefer speaking/workshops when education is primary; booths for high-volume discovery only with strong qualification; smaller community events when depth/trust dominates reach.

## Common failure patterns
Attending because competitors do, overstaffing booths, no technical objective, weak follow-up, counting badge scans as success, and ignoring preparation cost.

## Verification
Compare actual audience, meaningful technical interactions, content reuse, adoption signals, and feedback quality against planned outcomes and full cost.

## Expected output
A prioritized event portfolio with participation mode, owners, budget, technical plan, metrics, and post-event actions.

## Stop conditions
Decline when safety/code-of-conduct standards are inadequate, audience fit is unsupported, staffing cannot deliver credible technical engagement, or claims/demos are not ready.
