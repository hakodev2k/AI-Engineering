# Qualitative Coding and Thematic Analysis

## Purpose
Transform interviews, observations, diaries, and open-ended interaction data into defensible patterns without erasing contradictions or overstating prevalence.

## When to use
Use when research questions require understanding behaviors, mental models, motivations, strategies, failures, or contextual mechanisms.

## Inputs
Research questions, transcripts or notes, interaction artifacts, sampling information, system configuration, and study protocol.

## Context to inspect
Review how data was collected, moderator effects, participant composition, task conditions, model versions, missing sessions, and known biases.

## Core knowledge
Codes label evidence; themes explain meaningful patterns. Inductive and deductive coding can be combined. Frequency alone does not determine importance, especially for severe or rare failures. Researcher interpretation should remain traceable to source data.

## Procedure
1. Revisit research questions and intended claims.
2. Familiarize with a representative subset before finalizing codes.
3. Create initial codes from both research concepts and observed phenomena.
4. Define code boundaries and examples in a codebook.
5. Code data consistently while allowing justified code evolution.
6. Record analytic memos, contradictions, and negative cases.
7. Group related codes into candidate themes or behavioral patterns.
8. Test themes against raw evidence and across participant segments.
9. Separate prevalence statements from illustrative examples.
10. Identify alternative explanations and evidence that weakens each interpretation.
11. Link findings to product decisions without exceeding the sample's inference limits.

## Decision points
Use structured deductive coding for focused evaluation; inductive coding for poorly understood domains; multiple coders when reliability or stakeholder confidence warrants the cost, not as a ritual.

## Common failure patterns
Premature themes, counting quotes as population estimates, removing contradictory cases, vague code definitions, cherry-picked examples, and conflating participant explanations with observed behavior.

## Verification
Audit a sample from theme to coded evidence to raw source. Check negative cases and segment differences. Ensure claims match sampling and method limitations.

## Expected output
A traceable thematic synthesis with codebook, themes, supporting and contradictory evidence, segment differences, uncertainty, and implications.

## Stop conditions
Stop when source data quality is insufficient, consent does not permit the intended analysis, or missing context makes interpretation materially unreliable.
