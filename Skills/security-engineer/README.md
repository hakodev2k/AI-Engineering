# Security Engineer Skills

Task-focused procedures for AI-assisted work in the Security Engineer discipline. These files are Markdown guidance, require no installation, and should be loaded selectively according to the task.

Each skill file is self-contained and may be copied independently; this README, sibling skills, and any separate rule collection are optional context rather than runtime dependencies.

## Usage

1. Choose the smallest skill that matches the requested security outcome and the system boundary under review.
2. Supply the architecture, assets, trust boundaries, data classification, threat assumptions, environment, and acceptance criteria the skill requires.
3. If a separate rule collection is available, apply its relevant constraints as additional context.
4. Treat active testing, credential use, production access, exploitation, containment, disclosure, and risk acceptance as separately authorized actions.
5. Follow the skill's verification and stop conditions; record evidence, owners, residual risk, and required follow-up without exposing sensitive details.

These guides support defensive, authorized engineering work. They do not grant permission to scan, probe, exploit, access, disrupt, or modify a system.
