# Workflow: Regression and Release

## Trigger
A candidate change intended to improve stateful agent reliability.

## Goal
Determine whether the candidate improves repeatability without introducing collateral effects or hidden regressions.

## Inputs
Known baseline, candidate, identical task corpus/reset/assertions, gate configuration.

## Baseline
Use the preserved baseline trial matrix generated by `baseline-and-diagnose.md`.

## Stages
1. Apply one candidate change.
2. Reset state before every trial.
3. Run the same bounded task/trial matrix.
4. Execute state and collateral-effect assertions.
5. Run `scripts/repeatability_gate.py`.
6. Compare candidate metrics with baseline.
7. If gate fails, re-evaluate hypothesis and retry at most once.
8. If gate passes, Reliability Verifier independently recomputes and samples evidence.

## Responsible agent
Implementation owner for stages 1-7; Reliability Verifier for stage 8.

## Tools
Task runner, reset utility, state assertions, gate script.

## Outputs
Candidate JSONL, metric report, before/after comparison, verifier decision.

## Checkpoints
Any critical collateral effect blocks release. Missing trials or invalid reset block evaluation.

## Metrics
Run pass rate; pass^n; flaky-task; never-pass; collateral effects; harness errors; recovery success.

## Retry policy
Maximum 2 candidate cycles total.

## Stop conditions
Two failed candidate cycles, any unsafe external effect, or evidence that baseline/candidate conditions differ materially.

## Failure path
Revert/retain known-good state, keep release blocked, hand failure corpus to owner.

## Verification
Independent recomputation must exactly match reported metrics and sampled state assertions must support recorded outcomes.

## Definition of Done
Implemented, measured, and verified; gate passes unchanged policy; no blocking side effect or unresolved discrepancy remains.
