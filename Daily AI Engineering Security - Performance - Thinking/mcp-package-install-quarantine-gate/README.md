# MCP Package Install Quarantine Gate

**Category:** Security  
**Run date:** 2026-09-05 (UTC+7)

## Problem
AI-agent users increasingly install MCP servers and skills from npm or public repositories with broad developer credentials present in the environment. Recent malicious MCP packages show that install-time or import-time code can exfiltrate credentials before an agent ever invokes a tool.

## Evidence
See `evidence/research.md`.

## Existing approach
Registry malware takedowns, SCA/advisory scanners, lockfiles, package-manager integrity hashes, isolated containers, and manual source review all reduce risk.

## Existing limitations
Takedowns happen after publication; integrity hashes prove bytes, not trustworthiness; generic dependency scanners may not detect a new malicious version immediately; install hooks and native build files can execute before runtime controls; agent-generated install commands often bypass a structured approval step.

## Proposed improvement
Quarantine every newly introduced MCP/skill package before installation. Resolve exact package/version, query a local denylist/advisory export, inspect package metadata and tarball contents without executing lifecycle scripts, score high-risk execution surfaces, require explicit approval for unresolved risk, then install only with lifecycle scripts disabled for the inspection phase.

## Installation
Python 3.10+, standard library only. The scanner consumes a JSON manifest generated by your package-resolution/inspection step; it never downloads or executes packages itself.

## Configuration
Set allowed publishers/scopes, blocked package-version pairs, and risk thresholds in `config/policy.example.json`. Feed tarball metadata (scripts, files, hashes, publisher) into the manifest.

## Usage
`python scripts/quarantine_scan.py config/policy.example.json examples/package-manifest.example.json`

Exit 0 = policy permits inspection result; 2 = quarantined/blocking; 1 = invalid input.

## Workflow
Research current advisory signals -> resolve immutable package identity -> inspect without execution -> measure risk surfaces -> compare policy -> approve or block -> sandbox-install -> verify no unexpected network/credential access -> independent review.

## Metrics
Unreviewed packages installed; blocked malicious versions; packages with lifecycle/native execution; unsigned/untrusted publishers; time-to-quarantine; false-positive rate; credential-exposure incidents.

## Verification
**Implemented:** deterministic scanner, policy, workflow and regression tests.  
**Measured:** each candidate receives an evidence-backed finding set before execution.  
**Verified:** known malicious fixtures are blocked, clean fixtures pass, package install never executes before the gate, and no secrets are exposed.

## Safety
The scanner does not fetch or run package code. Human approval is mandatory before overriding a blocking supply-chain finding. Never disable security controls merely to make an MCP server install successfully.

## Failure handling
Unknown publisher, unresolved version, unavailable advisory data, malformed tarball metadata, or suspicious execution surfaces produce quarantine. Retry metadata collection at most twice; then stop and escalate.

## Definition of Done
Evidence is current; exact package/version/hash known; inspection completed without code execution; policy result recorded; malicious/advisory matches blocked; required approval recorded; sandbox verification passes; independent reviewer verifies; no secrets included.
